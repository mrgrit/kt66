# 시나리오 34종

원본은 `docs/시나리오_카탈로그.md` 다. 여기 있는 것은 그 카탈로그를 **이 랩에서 실제로
주입할 수 있는 형태**로 옮긴 것이다. 옮기면서 두 가지를 더했다.

## 왜 `impl` 을 붙였나

34개가 전부 도는 척하면 수업 중에 깨진다. 그래서 각 시나리오가 **지금 이 랩에서 실제로
주입되는지**를 스스로 밝힌다.

| 표시 | 뜻 | 수 |
|---|---|---|
| ● `ready` | 지금 그대로 주입된다. 강사 패널이나 한 줄 명령으로 끝 | 13 |
| ◐ `partial` | 주입은 되는데 스크립트가 없거나 제약이 있다. `note` 에 적었다 | 12 |
| ○ `planned` | 주입 수단이 아직 없다. **무엇이 없는지** `note` 에 적었다 | 9 |

`planned` 9종의 뿌리는 사실 셋뿐이다.

1. **3F 에 학습 워크로드가 없다** — Ollama 서빙만 있고 배치 잡·체크포인트·큐가 없다.
   → `INC-06`, `DR-02`, 그리고 `ENV-03` 의 `ai-training` 선택지가 비어 있는 것도 같은 원인.
2. **DGX 에 GPU 지표 exporter 가 없다** — XID·ECC 는 `/api/ps` 로는 안 보인다.
   → `GPU-01`, `GPU-02`. `GPU-04` 는 노드가 하나뿐이라 한 겹 더 멀다.
3. **요청 접수 창구(ITSM)와 백업 잡이 없다** — → `INC-02`, `INC-08`.
   `ENV-02`(CDU 누수)만 별개다. kt66 의 냉방 모델이 공랭이라 액체냉각 계통 자체가 없다.

## 왜 `evidence` 를 붙였나

카탈로그의 채점 원칙은 *"복구 성공 여부가 아니라 조치 순서와 근거 기록"* 이다. 그런데
근거가 **어디에** 있는지 시나리오가 말하지 않으면 강사마다 기준이 갈린다. 그래서 각
시나리오에 로그 경로·API·화면을 적어 두었다.

## 이름공간

`envsim/assets.yaml` 은 자기가 네 곳의 단일 진실원천이라고 주장한다 — 시뮬레이터, 관제
화면, CMDB, 그리고 **시나리오의 주입 대상**. 마지막 것은 강제하지 않으면 금세 거짓말이
된다. 시나리오에 `dgx-01` 이라 적어 두고 실제 자산이 `dgx-spark-01` 인 채로 학기가
시작되면 그 주차 수업이 통째로 날아간다.

```
python3 scenarios/validate.py
```

`target.asset` 이 자산 대장에 실재하는지, `envsim_fault` 의 고장 이름이 시뮬레이터가 아는
10종 안에 있는지, 주차별 배치가 카탈로그와 맞는지를 대조한다.

## cascade

카탈로그는 *"cascade 가 있는 시나리오는 미대응 시 후속 장애가 자동 발생한다"* 고 썼다.
지금 **자동 발생하는 것은 `ENV-03` 하나뿐**이다(배터리가 실제로 소진되면 전력이 없다).
나머지는 `enforced: false` 로 표시했다 — 선언은 되어 있으나 강사가 이어서 제시해야 한다.
`ENV-01` 의 "90초 후 GPU 스로틀" 을 자동화하려면 envsim 에 온도→성능 저하 연동이 필요하다.

## 카탈로그와 달라진 곳

- **SEC-04** 원본은 "mgmt 세그먼트 접근 시도" 인데 kt66 의 `mgmt` 는 논리 존이다(L2 경계가
  아니다). 실제로 격리된 세그먼트인 **`ot`(시설망)** 로 옮겼다. ips 의 `kt66ot` 테이블이
  ext→ot 를 차단하고 로그를 남기므로 증거가 오히려 확실하다.
- **DR-02** 는 카탈로그의 `INC-09b / DR-02` 를 `DR-02` 로 정리했다(`aliases` 에 남겼다).
- 자산 이름은 전부 kt66 의 실제 id 로 바꿨다 (`dgx-01` → `dgx-spark-01` 등).
