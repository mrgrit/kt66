# 사용자 업무 요청과 프로젝트 에이전트

사용자 업무는 **업무 요청** 메뉴(`/requests`, 근무자 운영의 8050 포트)에서 접수한다.
정기 점검과 같은 구독 CLI 실행기·동시 실행 한도를 사용하며, 대기 중 모델을 호출하지 않는다.
업무 화면에는 대화, 작업 계획, 프로젝트 역할, 산출물, 변경안과 처리 기록이 표시된다.

## 지원하는 업무

| 요청 예 | 실제 실행 범위 |
|---|---|
| 최근 5시간 SIEM 로그 분석 | 보관된 Wazuh 경보 파일과 압축 보관 파일을 기간·페이지별 조회 |
| 보안 시스템 IP 목록 | 자산 대장과 실제 Docker 네트워크 인터페이스 비교 |
| 특정 페이로드의 WAF 차단 규칙 | 지정 쿼리·폼 파라미터 값에 문자열이 포함되면 차단하는 ModSecurity 규칙 |
| 회사 홈페이지 개발과 WAF 아래 배포 | HTML/CSS/JavaScript 작성·검증 후 기존 WAF의 `/projects/<이름>/`에 정적 배포 |
| 기존 담당자가 커버하지 못하는 복합 업무 | 제공 도구 범위에서 프로젝트 역할 추가, 의존 관계별 작업 실행, 최종 결과 통합 |

SIEM 경보 보관 범위와 원시 로그 전체는 다르다. 없는 기간은 분석했다고 보고하지 않는다.
WAF의 지정 문자열 차단은 기존 CRS의 일반 SQLi 탐지와 별개다. 홈페이지 실행기는
패키지 설치, 서버 프로그램, DB·로그인·실결제를 지원하지 않는다. 없는 실행 기능은
에이전트를 추가해도 생기지 않으며, 필요한 정보 또는 실행 환경을 보고하고 대기한다.

## 요청과 실행

1. 강사 키로 업무 공간을 연다. 키는 요청 헤더로 전달하며 브라우저 영구 저장소에 저장하지 않는다.
2. 원하는 결과와 대상·조건을 적고 조회 전용 또는 파일 작성·변경안 준비 범위를 선택한다.
3. 세션 예산(기본 8, 최대 30)과 신규 역할 수(기본 3, 최대 6)를 설정한다.
4. 서비스데스크가 단순 조회를 처리하거나 작업 계획과 선후 관계를 등록한다.
5. 기존 담당자를 활용하고 부족한 역할만 기존 런타임·모델을 템플릿으로 추가한다.
6. 각 작업은 별도 세션과 도구 증거를 남긴다. 복합 업무는 마지막 검토 세션에서 통합한다.
7. 정보 부족·실행 실패·예산 부족·변경 검토 대기를 완료와 구분한다.

세션 예산은 배정된 계획·담당 작업·검토 세션의 총합이며 토큰 상한은 아니다.
전체 실행기의 동시 실행·일일 제한도 함께 적용된다. 실패와 구독 한도 초과는 반복 모델
호출로 숨기지 않고 사유를 남긴다. 후속 요청은 새 회차로 이어가며 기존 파일과 대화는 보존한다.
이전 회차의 미완료 작업과 미적용 변경안은 더 이상 실행하지 않는다.

프로젝트 에이전트는 해당 요청에서만 활동한다. 요청 완료·중지 후 보관하며 별도 정기
점검을 만들지 않는다. 상시 역할로 자동 승격하는 기능은 없다. 상시 운영이 필요하면
기존 근무자 운영 화면에서 조직·담당 범위를 정하여 등록한다.

## 변경 검토와 적용

홈페이지와 WAF 규칙은 격리된 Apache 컨테이너에서 검사한다. 후보 파일은 읽기 전용이고
호스트 인증 자료·외부 네트워크·공개 포트는 제공하지 않는다. 홈페이지는 로컬 링크와
JavaScript 구문도 검사한다. 브라우저 시각 검사나 결제 기능 검사까지 성공했다고 표시하지 않는다.

검증된 파일을 고정하고 해시·검사 결과·적용 내용을 변경안으로 남긴다. 사용자가 변경안의
**이 변경안 적용**을 누르면 러너가 확인한 버전을 적용한다. 홈페이지는 실제 응답 파일과
WAF 차단을 확인하고, WAF는 실제 Apache 포함·구문·재적재·HTTP 동작을 확인한다.
검증에 실패하면 해당 적용을 복구하고 실패를 표시한다. 적용 완료된 변경에는 되돌리기
버튼이 있다. 배포 후 다른 내용으로 수정된 파일은 자동 삭제하지 않는다.

요청 중지는 다음 도구 접근과 남은 작업을 막는다. 이미 진행 중인 단일 도구 호출은 끝날
수 있으며, 검증·적용 중에는 중지·후속 요청을 받지 않는다. 적용 중 러너가 중단되면
기록된 적용 의도와 파일 해시로 자신의 변경만 이어서 확인한다. 파일이 다르면 자동 덮어쓰지 않는다.

## 한국어 문서로 배우는 동작 변경

[교육용 원본 안내](../agents/native/README.md)에 수정 위치와 비교 실습을 정리했다.
업무 화면의 **지침 실습**에서 공통 `AGENTS.md`, 표준 역할 Markdown, 업무별
`SKILL.md`를 편집할 수 있다. 저장 전 백업과 동시 편집 충돌 검사를 수행한다.
수정 내용은 다음 세션에서 읽고 당시 사본은 실행 증거에 남긴다.

| 용도 | Claude | Codex |
|---|---|---|
| 공통 실행 지침 | `CLAUDE.md` → `AGENTS.md` | `AGENTS.md` |
| 역할 정의 | `.claude/agents/kt66-request-worker.md`를 CLI `--agents`/`--agent`에 연결 | `.codex/agents/kt66-request-worker.toml` 내보내기, 실제 세션에는 `AGENTS.md` 전달 |
| 스킬 사본 | `.claude/skills/<이름>/SKILL.md` | `.agents/skills/<이름>/SKILL.md` |

스킬 원본은 `agents/native/.agents/skills/`에 한 번만 작성한다. 필요한 스킬은
`skill_read`로 읽고 기록을 남긴다. 멀티에이전트 작업 큐는 별도 세션을 배정하며,
Claude Agent Teams나 Codex 내부 재귀 위임을 활성화하지 않는다. 로그인은 기존
Claude 구독·ChatGPT 계정을 사용하며 모델 API 키나 자동 API 전환은 사용하지 않는다.

## 관제와 저장 위치

- `agents/tickets/requests/<요청 ID>/request.json`: 대화·계획·역할·예산·변경안·처리 기록.
- 같은 디렉터리의 `workspace/`: 요청의 파일 산출물. 화면에서는 다운로드로 제공한다.
- `changes/`: 검증 당시 고정한 변경 파일과 적용 복구 기록.
- `agents/evidence/<실행 ID>/`: 요청, 지침·역할·스킬 사본, 세션 결과, 도구·파일 접근 기록.
- 4층 **AI 에이전트 관제**의 ‘사용자 업무’ 실행과 업무 화면을 연결한다.

요청과 산출물은 배포 환경별 실행 자료이므로 Git 추적에서 제외한다. 같은 실습 환경의
기존 에이전트 관제는 실행 증거를 공유하는 화면이다. 개인별 비공개 다중 사용자 시스템으로
격리하는 인증·권한 체계는 별도 기능이다.

## 다른 실습 PC에 배포할 때

러너 호스트에 Python·PyYAML, Docker CLI와 실행 권한, JavaScript 구문 검사용 Node.js,
사용할 Claude 또는 Codex CLI와 구독 로그인이 필요하다. 웹 서비스에는 Compose의
`web/request-rules`와 `web/request-rules.conf` 마운트를 함께 반영한다.
조직 정책·원본 지침은 저장소로 배포하고 요청·로그인 자료·실행 증거는 환경별로 관리한다.

## 근무자와 직접 대화하기

데이터센터 캐릭터의 **말 걸기** 또는 업무 공간의 **근무자 대화**를 이용합니다.
SOC 분석가를 고르고 ‘1시간 전부터 시스템이 좀 이상해. 로그 한번 봐줘.’처럼
메시지를 보내면 그 근무자의 구독 런타임·역할·조회 권한으로 조사합니다.
결과와 추가 질문은 같은 대화에 남고, 왼쪽 대화 목록에서 다시 이어갈 수 있습니다.
이전 대화는 다음 메시지를 처리할 때 전달되며 다른 대화의 내용은 섞이지 않습니다.

상대 시간은 메시지를 접수한 시각 기준입니다. 화면은 브라우저의 시간대를 전달하고,
API만 사용하며 시간대를 생략하면 UTC를 사용합니다. 조사한 기간과 실제 도구 호출은
대화의 조회 기록 및 실행 관제에서 확인할 수 있습니다. 인사·설명만 답한 경우에는
새 조회 근거가 없다는 표시가 나옵니다.

한 메시지에 한 세션을 배정하며 기본 대화 예산은 8세션입니다. 답변 중에는 다음
메시지를 보내지 않고 기다립니다. 대기·화면 새로고침에는 모델을 호출하지 않습니다.
예산을 소진하면 같은 화면에서 한도를 늘려 이어갈 수 있습니다. 직접 대화는 조회
전용이며 설정 변경·개발·여러 담당자의 협업은 기존 **업무 요청**으로 접수합니다.

API는 강사 키 인증 후 `POST /api/requests`에 `mode: "conversation"`,
`worker: "soc-analyst"`, `prompt`, `timezone: "Asia/Seoul"`을 보내면 됩니다.
담당자 목록은 `GET /api/request-workers`, 후속 메시지는 기존 요청의 `reply` API를
사용합니다. 새 대화는 서비스데스크·최종 검토자를 거치지 않고 선택한 담당자가
직접 처리합니다. 역할과 공통 한국어 지침은 실행마다 사본을 남깁니다.
