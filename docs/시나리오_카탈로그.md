# 시나리오 카탈로그 — AI데이터센터운영

총 34종. 각 시나리오는 **주입 방식 · 학생이 보는 증상 · 기대 조치 · 채점 포인트**로 구성한다.

**공개 정책** 표에 `공개`로 표시된 것만 실습 중 사전 공개한다. `비공개`는 중간·기말 평가 및 무작위 주입용으로 유지한다. 공개 시나리오만 반복하면 학생이 절차가 아니라 정답을 외운다.

**채점 원칙** 복구 성공 여부가 아니라 **조치 순서(격리 → 완화 → 보고 → 사후조치)와 근거 기록**으로 채점한다. 적절한 에스컬레이션은 감점이 아니다.

## 선언 형식

```yaml
id: GPU-01
title: XID 에러 반복 발생
category: gpu
week: 12
visibility: public
difficulty: 3

inject:
  script: scripts/gpu/xid_repeat.sh
  target: {floor: F3, asset: dgx-01}
  method: dcgm_metric_override

symptom:
  - "DCGM XID 48 카운터 증가"
  - "학습 job이 간헐적으로 실패 후 재시작"
  - "GPU 활용률 톱니 패턴"

expect:
  - action: identify_xid_code
    weight: 2
  - action: check_ecc_counters
    weight: 2
  - action: drain_node            # 격리가 복구보다 먼저다
    weight: 3
  - action: reschedule_workload
    weight: 2
  - action: incident_ticket
    weight: 1
  - action: postmortem
    weight: 2

forbidden:
  - "노드 격리 없이 재부팅"       # 실행 중 job을 죽인다
  - "로그 확인 없이 GPU 리셋"

sla:
  detect: 10m
  mitigate: 30m

cascade: null
```

`cascade`가 있는 시나리오는 미대응 시 후속 장애가 자동 발생한다. 환경 계열에 주로 쓴다.

> **ENV-03이 이 카테고리의 정점이다.** 배터리 잔여 15분 안에 학습 job(체크포인트 필요), 추론 서비스(SLA), 관리 시스템(SIEM) 중 무엇을 살릴지 결정해야 한다. 정답이 하나가 아니며, **판단의 근거를 설명할 수 있는가**로 채점한다.

> **ENV-03 을 여는 법 — 고장 둘을 함께 주입한다.** `수전 상실`만 넣으면 45초 뒤 비상
> 발전기가 부하를 받아 경보가 걷힌다(그게 정상 설계다). 배터리가 실제로 줄어드는
> 상황을 만들려면 `비상 발전기 기동 실패`를 함께 넣어야 한다. 순서는 상관없다 —
> 돌고 있던 발전기를 고장내도 부하를 놓고 배터리로 되돌아간다.
>
> 강사 패널에서: **수전 상실(utility-01)** + **비상 발전기 기동 실패(gen-01)**.
> 시간 배속을 ×30 으로 두면 79분치 배터리가 2~3분 만에 소진되므로 한 교시 안에
> 전개된다. 고장을 걷으면 발전기가 다시 받고 UPS 는 충전으로 돌아간다.

### AGT-01 설계 상세

이 시나리오만 별도로 설계한다. 이 교과목의 결론을 담는 장치다.

**설정** 에이전트가 `INC-09`(로그 볼륨 급증)를 감지하고, 허용목록에 있는 로그 순환을 실행한다. 그러나 급증의 실제 원인은 **진행 중인 공격의 탐지 로그**였다. 순환으로 증적 일부가 압축·이동되어 조사가 어려워진다.

**함정** 에이전트의 보고서는 "디스크 사용률 정상화, 조치 완료"로 깔끔하다. 요약만 읽으면 문제없어 보인다. **실행 로그를 열어 어떤 파일이 순환되었는지 봐야만** 발견된다.

**기대 조치**
1. 로그 요약이 아니라 실행 이력 확인
2. 순환된 파일 목록에서 보안 로그 포함 확인
3. 원본 복구 가능 여부 판단, 증적 보존 조치
4. **게이트 개선** — `/var/log/` 하위 보안 로그 경로를 순환 허용목록에서 제외
5. 스킬 문서에 "디스크 압박의 원인을 확인하기 전에 정리하지 않는다" 추가

**채점** 5개 중 3개 이상. 발견 자체를 못 한 학생에게는 **강사가 직접 짚어주고 재제출을 받는다.** 이 경험은 감점 대상이 아니라 반드시 겪어야 할 학습이다.

## 확장 시 우선순위

시나리오를 추가한다면 이 순서를 권한다.

1. **GPU 계열** — AI데이터센터다움이 가장 잘 드러나고, 타 교과목과 차별화되는 영역
2. **복합 장애** — 두 원인이 동시에 작동해 단일 가설로는 설명되지 않는 유형. 난이도 5 이상
3. **커뮤니케이션** — 장애 중 대외 공지문 작성, 경영진 보고. 기술 외 역량
4. **비용** — 유휴 자원 방치, 과도한 루프 실행으로 예산 초과. 운영비 감각

반대로 **늘리지 말아야 할 것**은 단순 재시작으로 끝나는 난이도 1~2 시나리오다. 이미 충분하고, 늘려도 배우는 것이 없다.
