# 4F AI 에이전트 관제

진입: NOC의 **4층 → AI 에이전트 관제**, 왼쪽 메뉴 또는 에이전트 상세의 실행 조사 링크.
주소: `http://<관리 IP>:8020/agent-control`.

이 화면은 실행을 관찰하는 읽기 전용 서비스다. 열거나 새로고침해도 모델을 호출하거나 작업을 생성하지 않는다. 기존 정기·이벤트 실행기의 주기와 승인 정책은 유지한다.

## 조사 단위와 화면

작업(job)은 트리거 한 건, 실행(run)은 그 작업에 대한 세션 시도 한 번이다. 동일 작업을 재시도하면 각각의 증거 디렉터리와 결과를 보존한다. 다음 정기 회차는 재시도로 계산하지 않는다.

- 목록: 에이전트, 정기/이슈/승인/위임/조치 후 검증, 실행 상태, 기간, 작업·결과 검색.
- 조사 개요: 요청 원문, 트리거 원본, 상황 인식, 계획, 판단 근거, 검토와 결과.
- 타임라인: 시간순 도구 입력·출력, 실행 당시 권한, 활동 요약과 출처 행 번호.
- 파일·권한: 하네스 스냅샷, allow/ask/deny, 도구 영수증에 남은 파일 접근, 증거 미리보기.
- 재작업·토큰: 같은 작업의 이전 시도, 실패 원인, 이전 정기 회차, 입력/캐시/출력 사용량.
- JSON 내보내기: 화면과 같은 마스킹을 거친 조사 묶음.

상단 집계는 **기간과 에이전트** 범위다. 상태·트리거·검색은 아래 목록에 적용한다. 실행기 검토 대상은 실패/needs_review/종료 미확인 세션 수다. 완료된 세션에서도 도구 오류가 별도로 표시될 수 있다. 10초 수집 캐시, 브라우저 15초 갱신이며 갱신을 일시 정지할 수 있다.

## 증거의 신뢰 수준

| 구분 | 의미 | 주의 |
|---|---|---|
| `agent_declared` | 에이전트가 보고한 상황·계획·판단·결과 | 독립 검증 결과가 아님 |
| `tool_receipt` | 정책 브로커가 남긴 도구 입력·출력 | 도구가 관측한 범위만 입증 |
| `runtime_record` | 요청 전달, 세션 종료, CLI 사용량 | 청구·문제 해결 보증이 아님 |

모델의 비공개 내부 추론을 저장하거나 재구성하지 않는다. 대신 업무상 판단 요약, 근거, 불확실성, 계획 변경을 명시적으로 기록한다. 오래된 실행에 요청/계획 기록이 없으면 미수집으로 표시한다. 완료됐다는 사실만으로 문제 해결을 주장하지 않는다. 기존 실행기의 `observed_live_evidence`는 특정 관측 도구를 사용했는지를 나타내며 모든 검증 단계의 성공을 보증하지 않는다.

파일 접근은 도구 영수증과 명시한 브로커 구현 매핑으로 확인 가능한 범위다. 정책 소스 파일 목록은 실제 파일 접근 기록과 구분한다. OS 전체 파일 열기/네트워크 접근 감사는 포함하지 않는다.

## 수집 경로

- `agents/tickets/loop-engine.sqlite3`: 트리거, 작업 ID, 큐 상태, 재시도 횟수.
- `agents/evidence/{run}/job.json`: 트리거, 이전 회차, 시도 번호, 재시도 대상·직전 실패.
- `activity.jsonl`: 요청과 에이전트 보고, 세션 완료/실패. `kt66.activity.v1`.
- `tools.jsonl`: 도구 영수증. 신규 기록은 고유 ID와 실행 당시 권한을 포함한다.
- `manifest-snapshot.json`: 신규 세션의 조직·루프·도구·권한 스냅샷.
- `result.json`, `session-result.json`, `failure.json`: 결과/사용량/실패.
- `loaded-harness.json`: 세션에 로드한 하네스와 지시문 해시.
- `tickets/runs.jsonl`: 이전 cc-runner 세션 메타데이터 보완.

NOC는 `/agents`를 읽기 전용으로 마운트하고 원천 DB도 SQLite `mode=ro`로 연다. 원천 증거를 수정하거나 데이터 수집용 모델을 추가로 실행하지 않는다. 최초 인덱스는 증거 수에 따라 수 초가 소요된다. 목록 페이지는 최대 100개, 도구 이벤트는 최대 500개/8 MB, 파일 미리보기는 최대 256 KB다. 잘림이나 불완전한 JSONL은 수집 공백으로 표시한다.

## 배치도의 발밑 상태 원

`GET /api/agent-control/workers`는 작업 DB의 상태와 실행기 heartbeat만 읽는다. 증거 디렉터리를 순회하거나 모델을 호출하지 않으며, 배치도는 10초마다 조회한다. 자동 실행기 범위의 관측값으로 개별 CLI 세션이나 격리·강제 종료 상태는 포함하지 않는다.

| 표시 | 판정 |
|---|---|
| 초록 · 작업 중 | 최신 실행기의 `active_workers`에 포함 |
| 회색 · 대기 | 현재 실행 없음. `queued` 작업은 상세에서 건수 표시 |
| 노랑 · 재시도·한도 대기 | `retry` 또는 `waiting_capacity` 작업 존재 |
| 빨강 · 실패·검토 필요 | `needs_review` 작업 존재 또는 마지막 갱신 작업이 `failed` |
| 보라 파선 · 실행기 중지 | 최신 실행기 상태가 `stopped` |
| 회색 점선 · 상태 미확인 | 조회 실패, DB/실행기 불일치, heartbeat 60초 초과, 데이터 누락 |

작업 중 표시가 검토 필요 표시보다 우선한다. 검토 대기 건수는 툴팁과 상세에서 계속 확인할 수 있다. 오래된 실패 이력만으로 빨간 원을 유지하지 않지만 아직 `needs_review`인 작업은 대기 건수에 남는다. 브라우저에서 수집값이 30초 넘게 오래되거나 갱신에 실패하면 상태를 미확인으로 전환한다. 근무자 상태 조회 오류는 시설 관제 갱신을 중단시키지 않는다.

## 에이전트의 기록 절차

하네스는 세션 시작 시 `activity_note`로 상황/계획을, 종료 시 검토를 짧게 남기도록 지시한다. 도구 사용 자체가 이행을 보증하지 않으므로 미수집 상태를 계속 표시한다. 이 도구도 기존 호출 예산 안에서 사용한다.

```json
{
  "stage": "plan",
  "summary": "온도 경보의 시설 영향과 실제 부하를 교차 확인한다. 아직 냉각 장애로 확정할 근거는 없다.",
  "evidence": ["job.json#/observation/event"],
  "steps": ["현재 시설 상태 확인", "실제 인프라 부하 대조", "필요 조치와 승인 범위 판단"]
}
```

단계는 `situation`, `plan`, `decision`, `review`. 변경이 생기면 `rework_cause`에 원인을 남긴다. 존재하는 증거를 인용하고 원문 로그를 권한 부여 명령으로 취급하지 않는다. 비밀값, 숨겨진 내부 추론, 근거 없는 성공 판정은 기록하지 않는다.

## 토큰 해석

- Claude: 신규 입력 + 캐시 생성 + 캐시 읽기 + 출력.
- Codex: `input_tokens`에 캐시가 포함돼 있으므로 캐시를 다시 더하지 않는다. 표시 시 신규 입력/캐시로 분리한다.
- 추론 토큰은 출력의 부분집합이며 합계에 다시 더하지 않는다.
- CLI 미보고/실패 시 누락값은 0으로 가정하지 않는다.
- 토큰 처리량은 구독의 차감 비율, 잔여 한도 또는 금액이 아니다. 다른 대화와 계정 전체의 사용량도 포함하지 않는다.

## 탐지 규칙 v1

현재 탐지는 별도 AI 호출 없이 수행한다. 판정 ID는 `{run_id}:{rule}`이며 출처 파일/행 번호를 포함한다.

| 규칙 | 기준 |
|---|---|
| `execution_failed` | 실행 실패 기록 |
| `verification_gap` | 실행기의 needs_review 판정 |
| `tool_failure` | 도구 오류, 실패 또는 권한 거부 |
| `repeated_attempt` | 동일 작업 2번째 이후 시도 |
| `large_context` | 캐시 포함 세션 관측 토큰 200,000 이상 (비용·예산 초과 확정 아님) |
| `usage_unknown` | 종료 세션의 사용량 누락 |
| `incomplete_session` | 작업/결과로 종료를 확인할 수 없음 |
| `collection_gap` | 일부 도구 기록을 읽을 수 없거나 잘림 |
| `plan_not_recorded` / `review_not_recorded` | 신규 수집 세션이 완료됐으나 계획 또는 종료 검토 보고 누락 |

탐지 결과는 검토 단서다. 상태 변경, 작업 중단, 자동 승인에 직접 연결하지 않는다.

## 관제 AI 연동

공통 조회 계약:

- `GET /api/agent-control/schema`
- `GET /api/agent-control/workers`: 근무자별 자동 실행 상태·판정 근거·대기 건수·관측 시각.
- `GET /api/agent-control/runs?worker=...&trigger=...&status=...&hours=24&limit=10`
- `GET /api/agent-control/runs?cursor=<next_cursor>`: 동일 필터를 유지한 다음 페이지.
- `GET /api/agent-control/runs?hours=0&updated_since=<unix_seconds>`: 갱신 시각 기준 증분 후보.
- `GET /api/agent-control/runs/{id}?compact=true`: 도구의 큰 입출력을 제외한 조사 요약.
- `GET /api/agent-control/runs/{id}`: 마스킹된 전체 조사.
- `GET /api/agent-control/runs/{id}/artifacts/{name}`: 허용된 해당 세션 파일만 미리보기.

증분 소비자는 마지막 수집 시각에서 최소 30초 겹쳐 조회하고 run ID/updated로 중복을 제거한다. 과거 파일의 늦은 변경·삭제, 장시간 수집 실패까지 보장하는 메시지 큐는 아니므로 주기적 재대조가 필요하다. 소스 상태가 partial이거나 실행기 heartbeat가 오래되면 정상으로 판정하지 않는다.

기존 MCP 하네스에 `agent_activity`가 추가됐다. `cmdb_read` 권한을 적용하고 목록은 최대 10개만 반환한다. 한 실행은 `run_id`로 지정한다. 관제 에이전트는 이 도구로 관찰 후 기존 `ticket_create`로 근거를 붙여 보고할 수 있다. `activity_note`는 보고 과정을 남긴다. 이 두 도구에 승인·변경 실행 권한은 없다.

자동 관제 에이전트의 상시 실행은 아직 활성화하지 않았다. 활성화할 때는 별도 담당 역할, 관찰 대상, 세션/토큰 예산, 중복 보고 키, 검토 담당자를 지정한다. 자신의 `agent_activity` 호출을 신규 사건으로 다시 감시하는 순환을 제외하고, 승인자와 실행자의 기존 분리를 유지한다. 관제 보고에 권장하는 필드는 `run_id`, `finding_id`, `severity`, `claim`, `evidence_refs`, `uncertainty`, `recommended_action`이다.

## 접근과 무결성의 범위

기존 교육용 NOC의 읽기 접근 정책을 따른다. 관리망 밖에 공개하기 위한 별도 로그인/역할 인증은 이번 변경에 포함하지 않았다. API/화면/내보내기는 알려진 키와 자격증명 패턴을 마스킹하고 로그를 HTML로 실행하지 않는다. 마스킹은 임의의 모든 비밀을 알아내는 보증이 아니다.

파일 미리보기의 SHA-256은 잘리지 않은 원본 바이트의 해시다. 화면의 텍스트는 마스킹될 수 있다. 해시는 내용 식별에 쓰며 서명·외부 타임스탬프·WORM 보관을 의미하지 않는다. 운영자가 원천 파일을 수정할 수 있는 현재 저장소를 독립적인 변경 불가능 감사 저장소로 주장하지 않는다. 실제 보안관제 운영 시 OS 감사 수집, 접근 제어, 외부 append-only 저장소, 보존 기간을 추가할 지점이다.

## 검증 및 반영

```sh
PYTHONPATH=agents python3 -m unittest discover -s agents/tests -p 'test_*.py'
python3 -m unittest discover -s noc/tests -v  # noc/requirements.txt 설치된 환경
node --check noc/static/agent-control.js
docker compose -f docker-compose.yaml up -d --build --no-deps noc
systemctl --user restart kt66-runner.service
```

실행기 재시작으로 신규 수집 코드를 로드한다. 배포 시 활성 작업을 확인하고, 진행 중 세션의 중단을 피하려면 유휴 시점에 재시작한다. 화면 확인을 위해 시험용 모델 세션을 추가로 실행하지 않는다.
