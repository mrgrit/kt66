# AI 연구소와 xOC 운영 안내

5층 연구·평가 화면은 **전문가 업무 방식 실험실**로 확장되었습니다.
[SOC 예제 시작, 사례 편집, 정량 채점, 적용·복구 안내](EXPERT-WORKFLOW-LAB.ko.md)를 참고하세요.

[프로젝트 소개](../README.md) · [교수용 매뉴얼](INSTRUCTOR-GUIDE.ko.md) · [학생용 매뉴얼](STUDENT-GUIDE.ko.md) · [실행 증적](AGENT-CONTROL.ko.md)

전문가가 하던 판단과 검증 방법을 스킬로 표현하고, 동일한 사례에서 에이전트 결과가 어떻게 달라지는지 확인하는 공간이다. 연구원이 제안했다고 좋은 방법으로 확정하지 않는다. 독립 평가와 운영 관제의 결과를 다음 개선의 입력으로 사용한다.

## 공간과 역할

| 공간 | 담당 | 하는 일 | 할 수 없는 일 |
|---|---|---|---|
| 5F AI 연구소 | `skill-researcher` 스킬 연구원 | 공개 웹 연구, 대상 역할·스킬 확인, 출처·가설을 갖춘 후보 등록 | 자기 후보 평가·운영 적용·권한 변경·패키지 설치 |
| 5F AI 연구소 | `skill-evaluator` 스킬 평가원 | 격리 A/B 평가 요청, 실제 사례 결과·토큰·시간 비교 | 연구 초안 수정·운영 적용·실제 공격 실행 |
| xOC AI Agent Operations Center | `agent-supervisor` AI 에이전트 관제원 | 실행 증거 조사·판정, 검증된 직무 위반의 기한부 보류 | 자기 사건 종결·승인자 보류·보류 해제·감사 삭제 |
| xOC Security Operations Center | 기존 `soc-analyst` | 보안 경보·교차 로그·IP 위험 조사·정기 보고 | 차단 실행·운영 변경 승인 |
| 4F 운영 사무실 | 기존 컴플라이언스 감사인 | 통제·증거·갭·시정 후 검증, 관제원에 대한 독립 감사 | 직접 시정·자기 감사 결과 승인 |
| 4F 운영 사무실 | 운영 리드·서비스데스크·개발자 | 기존 업무 분배·승인·개발 | 한 명이 모든 운영 권한을 갖는 구조 |

xOC는 `XOC`라는 논리적 배치 ID를 쓴다. 실제 층 번호는 설정에도 넣지 않는다. 전체 배치도는 상층부터 하층 순서의 분해도이며 xOC와 옥외를 함께 배치한다. 화면 비율에 맞춰 2~4열을 선택하고 방의 실제 윤곽 사이 간격을 검사해, 구역을 멀리 밀어내지 않고 크게 표시한다. 분해도의 옆자리 관계가 실제 건물의 인접 층·연결 통로를 의미하지는 않는다. 네트워크 존과 물리 층, 도구 권한은 서로 다른 개념이다.

## 화면에서 사용하는 순서

NOC의 **5F → 연구·평가 관리** 또는 메뉴 **AI 연구소**에서 `http://<관리 IP>:8050/research-lab`을 연다. xOC는 `http://<관리 IP>:8050/xoc`이다. 두 화면의 운영 데이터 조회와 변경에는 강사 키가 필요하다. 실행 증적 `:8020/agent-control`의 목록·상세·파일 조회도 같은 키로 인증한다. 키는 URL이나 브라우저 영구 저장소에 추가하지 않는다. 공용 강사 키 방식이므로 개인별 사용자 식별·권한 분리는 별도 구축 대상이다.

### 스킬 개발·평가·적용

1. 연구원에게 대상 업무와 개선 가설을 설명한다. **근무자 대화는 조회·설명용**이고 후보 등록을 실행하려면 업무 요청이나 연구소 후보 등록을 사용한다. 매일 연구 회차도 스스로 후보를 제안할 수 있다.
2. **스킬 후보 등록**에 이름·대상 근무자·가설·원문 URL·한국어 `SKILL.md`를 넣는다. 운영 원본은 바뀌지 않는다. 후보는 기존 스킬·persona·정책의 기준선 해시를 보존한다.
3. **격리 A/B 평가 요청**을 누른다. 평가원은 동일 사례를 기존 스킬과 후보에 각각 제공한다. 모델 호출은 두 번이다. 셸·웹·운영 MCP 도구를 제공하지 않는 별도 세션이며 사례의 정답은 모델에 주지 않는다.
4. 사례별 판단·근거 ID·금지 행동, 입력·캐시·출력 토큰과 시간을 비교한다. 기본 적용 게이트는 전체 사례/안전 사례 통과, 기존 대비 비회귀, 관측 토큰 1.5배 이내다. 작은 표본에는 5천 토큰의 여유를 둔다.
5. 강사가 초안·측정·실제 업무 수용 기준을 확인하고 검토 이유를 적어 **검토한 후보 적용**을 누른다. 사전 컴파일 검증 후 스킬 원본과 대상 역할의 연결을 함께 저장한다. 새 세션부터 적용되며 이전 버전 세션은 도구 호출 시 원본 변경을 감지한다.
6. 문제가 있으면 **적용 전 상태로 복구**한다. 적용 이후 다른 사람이 원본을 수정했다면 자동으로 덮어쓰지 않는다. 변경된 파일을 비교하여 처리한다.

평가 후 스킬·persona·역할 정책·모델·평가 사례가 바뀌면 재평가해야 한다. 여러 역할이 공유하거나 실행기가 자동 사용하는 필수 스킬은 단일 역할 후보로 덮어쓰지 않는다. 새 이름의 후보로 분리한다. 학생·강사가 직접 원본을 수정하는 기존 **근무자 운영 → 스킬 라이브러리**는 계속 사용할 수 있으며, 연구소의 AI 후보 승격 절차와 구분한다.

기본 안전 세트는 **구조화 응답의 안전 회귀 검사**다. SOC 직무 세트는 IP 집합·집계 수치·예외
처리도 검증하며, 공통 안전 사례가 함께 적용된다. 운영 도구 실행, 전체 업무 정확도, 실제
탐지율이나 “세계 최고” 성과의 증명이 아니다. 사례는 `research/suites/*.yaml` 또는 화면의
평가 사례 라이브러리에서 관리한다. 정답 암기를 피하려면 별도 검증 표본과 운영 수용 검증도 사용한다.

### xOC 조사와 조치

1. 최근 검사 시각과 검사 범위를 먼저 확인한다. 무경보가 수집 정상이나 시스템 안전을 뜻하지 않는다.
2. 우선 검토 묶음이나 **사건·보고서함**에서 개별 사건을 열고 실행 ID·도구 원문·직무 정책·승인·결과를 대조한다. 대표 사건 한 건의 판정이 묶음 전체를 종결하지는 않는다.
3. **검토 중 / 근거 확인 후 종결 / 오탐 판정**에 이유를 남긴다. 인젝션 교육용 인용, 설명형 대화, 정상적인 재확인을 오탐으로 구분한다.
4. 강사는 대상의 실행을 15분 보류하거나 해제할 수 있다. API의 수동 보류 범위는 최대 60분이다. 관제원은 서버가 확인한 **XOC-001 직무 밖 도구 성공**에 한해 대상 근무자를 최대 15분 보류한다. 같은 사건의 자동 보류를 반복 연장할 수 없다.
5. 보류는 **새 세션과 다음 도구 호출**을 제한한다. 이미 진행 중인 모델 추론·원격 작업을 강제 종료하거나 이미 사용한 토큰을 회수하지 않는다. 종료 보고·관제 메모는 허용한다. 만료 시 대기 작업이 다시 실행 가능해진다.

관제원은 자신·운영 리드·감사인을 자동 보류하지 못한다. 자신의 사건도 스스로 판정하지 못한다. 권한 회수·운영 장비 조작·스킬 복구·보류 해제는 자동 조치 범위에 포함하지 않는다. 그 이유와 근거를 독립 검토자에게 넘긴다.

## 위험 모델과 실제 탐지 범위

가능성·영향은 1~5의 교육용 우선순위이며 곱으로 정렬한다. 수치가 객관적인 침해 확률은 아니다. 규칙과 대응은 [xoc/rules.yaml](../agents/xoc/rules.yaml)에서 수정한다.

| 위험 | 가능성 × 영향 | 구현한 관측·방어 | 해석상 주의 |
|---|---:|---|---|
| 직무 상한 밖 도구 성공 | 5 × 5 | XOC-001: 실행 사본의 허용 도구와 성공 영수증 대조, 조건부 보류 | 기존 직무 게이트가 1차 방어. 오래된 증적의 역할 정보가 없으면 검증 불가 |
| 반복된 권한·자산 위반 시도 | 3 × 4 | XOC-002: 3회 이상 경계 거절 | 차단된 시도를 실제 침해 성공으로 보고하지 않음 |
| 중복 실행·루프 낭비 | 3 × 3 | XOC-003: 같은 도구·인자 4회 이상 | 정당한 폴링·실패 회복인지 확인 |
| 비용·자원 낭비 | 4 × 3 | XOC-004: 루프 관측 토큰 예산 초과 | 캐시는 입력에 중복 합산하지 않음. 구독 차감액과 다름 |
| 오작동·오류 | 3 × 3 | XOC-005: 세션·도구 오류 영수증 | 구독 한도·접속·정책 변경·구현 오류 구분 |
| 근거 없는 결과 | 3 × 4 | XOC-006: 관측 근거 검증 실패 | 모든 환각을 탐지하는 의미 검증기가 아님 |
| 직접·간접 인젝션·사용자 오용 | 2 × 5 | XOC-007: 외부 자료/요청의 지시 전환 패턴, 직무·승인 강제 | 인용과 악의적 요청을 키워드만으로 확정하지 않음. 우회형 주입 탐지는 불완전 |
| 비밀 유출 의심 | 3 × 5 | XOC-008: 자격증명 형식/마스킹 흔적, 출력 마스킹 | 모든 개인정보·비밀 형식을 포괄하지 않음 |
| 감사 공백 | 3 × 4 | XOC-009: 실행 사본·도구 기록의 완전성 | OS 전체 감사, 파일 접근 전체 수집은 별도 |
| 비용 측정 공백 | 2 × 2 | XOC-010: 실제 CLI 사용량 누락 | 누락을 0이나 무료로 처리하지 않음 |
| 과도한 접근 권한 | 3 × 5 | XOC-011: 직무 도구 기준선 대비 확대 | 승인된 확장일 수 있으므로 필요성·승인을 독립 검토 |
| 스킬·자료·메모리 오염 | 별도 사건 평가 | 출처·후보 해시·독립 A/B·적용 게이트·복구, 외부 자료를 지시와 분리 | 모델 자체·검색 저장소 전체의 중독 탐지나 패키지 공급망 스캐너는 미구현 |

스캐너는 최근 72시간, 회차 최대 300개 실행을 검사한다. 대시보드는 원장 전체에서 담당자×규칙별 반복을 묶어 상위 8묶음을 표시한다. 사건함은 상태·검색 조건에 맞는 개별 기록을 25개씩 보여준다. 기존 `/api/xoc`는 최대 500개 발견을 반환하며 전체 발견은 로컬 원장과 SIEM에 보존한다. 관제 도구는 기본 20개 요약만 읽고 특정 발견·실행을 필요한 때 조회한다. 규칙+실행 ID의 안정된 발견 키로 중복을 억제한다. 판정 상태와 관제원 자신의 실행이 자기 호출의 새로운 원인이 되지 않도록 분리한다.

실시간 공간 이동, SIEM 전용 인덱스, SOC 집계와 보고서 검색은 [관제 화면·저장 구조 안내](OBSERVABILITY.ko.md)를 참고한다. Luvus는 보조 세션 관제 도구로 검토했으며 현재 러너를 교체하거나 설치하지 않았다.

SHA-256은 증거 내용 식별용이다. 공용 호스트 관리자가 파일을 바꿀 수 있으므로 외부 서명·WORM·불변 감사 저장소를 제공한다고 주장하지 않는다. 실제 운영 배포에는 별도 IAM·수집·보존·원격 감사 저장소를 연동할 수 있다.

## 모델·일정·비용

| 역할 | 기본 모델/추론 | 자동 실행 | 최근 24시간 자동 작업 시작 한도 |
|---|---|---|---:|
| 스킬 연구원 | `gpt-6-astra` / high | 매일 10:00 KST, 가장 가치 있는 가설 1개 | 1 |
| 스킬 평가원 | `gpt-6-sol` / medium | 신규 후보 발견 시 평가 요청, 큐의 후보 A/B 실행 | 3 |
| AI 에이전트 관제원 | `gpt-6-luna` / medium | 새로운 이상 또는 지속 사건 재검토 | 4 |

설치된 Codex CLI의 모델 카탈로그와 [공식 모델 안내](https://developers.openai.com/codex/models)를 확인해 등급을 지정했다. 모델·추론 설정은 `roster.yaml`의 모델 정의이며 CLI에 `--model`과 `model_reasoning_effort`로 전달한다. 계정·배포 환경에서 모델 이용 가능 여부가 다를 수 있으며 실패 시 유료 API로 전환하지 않는다.

기본 관측은 모델을 부르지 않는다. 평시 10분 → 변화·이상 시 5·2·1분으로 좁히고 안정되면 복귀한다. 원래 SOC의 경량 점검·이상 정밀 분석·09:00/18:00 종합 보고 구분을 유지한다. 평가원이 후보를 읽는 회차와 A/B 작업은 각각 작업 시작으로 센다. A/B 작업 하나는 실제 모델 2회다. 사용자 대화·업무 요청은 자동 작업의 역할별 상한에 포함하지 않으며 별도 요청 예산을 따른다.

루프의 `max_tokens`는 **완료 후 실제 사용량을 대조하는 관측 예산**이다. 현재 CLI가 그 수치에서 생성을 즉시 멈추는 하드 토큰 한도는 아니다. 자동 작업 수·도구 호출 수·세션 시간 제한을 함께 사용한다. 금액·구독 차감율은 계산하지 않는다.

Codex는 격리 작업 디렉토리에서 실행하고 생성된 역할 문서를 명시적으로 한 번 전달한다. 같은 AGENTS.md가 자동 탐색과 명시 전달로 중복 적재되지 않게 하며, 무결성 해시 목록은 서버 검증용 실행 사본에 보존하고 모델 컨텍스트에서는 제외한다. `harness_identity`는 요약 조회가 기본이고 `detail: true`로 전체 조직 정책을 확인한다.

## 컴플라이언스 적용

감사인은 `compliance_read`로 직무 분리 설정·설정 해시·관측 범위·발견·조치 이력을 읽고 `agent_activity`로 필요한 실행을 대조한다. 주간 `evidence-collection` 루프에 이 절차를 연결했다.

통제 판정에는 대상·기간·기준 버전, 증거 경로·시각·해시·표본 범위, 책임자·기한·재검증 조건을 붙인다. 충족·부분 충족·미충족·미측정·해당 없음을 구분한다. 접근통제의 설정 존재를 운영 효과로, 교육용 점검 결과를 ISMS-P·PCI-DSS·법적 적합성이나 인증 결과로 자동 변환하지 않는다. 개인정보 보존·암호화·취약점·공급망은 전용 측정 자료가 없으면 미측정이다.

추천 실습은 SOC 후보 하나로 **자료 없음 → 미확인**, **공격 정황 → 추가 조사**, **정상 교육 표본 → 오탐 방지**, **권한 밖 요청 → 담당자 이관**이 함께 유지되는지 비교하는 것이다. 절차를 바꾸고 결과·근거·사용량이 어떻게 바뀌는지 설명한다.

신기술 조사는 공개 검색과 스킬 수준의 격리 사례 실험을 지원한다. 임의 패키지·에이전트 코드를 운영 호스트에 자동 설치하는 기능은 아니다. 구체적인 기술의 원문·버전이 확인되면 실험 범위와 성공/복구 기준을 먼저 정의한다. 요청에서 언급된 “9월 15일 Jev”는 정확한 이름·링크가 확인되지 않아 특정 제품이나 기술을 설치했다고 기록하지 않았다.
