kt66 실습 환경 — CCC 인프라 단일 VM Docker 버전

이 페이지는 kt66-web (Apache + ModSecurity) 가 응답한 랜딩 페이지입니다. 모든 취약 사이트 트래픽은 web 의 ModSecurity 검사를 통과한 후 백엔드 컨테이너로 전달됩니다.

미니 AI데이터센터 — 관제와 운영

4개 층(1F 시설 · 2F 네트워크/보안 · 3F AI 전산실 · 4F 운영)을 가진 데이터센터를 컨테이너로 세운 것. 전력·발열·존 경계는 가상이지만 부하와 고장은 실제로 랩에 적용된다 — 3F 에 부하를 걸면 온도가 진짜로 오르고, 주입한 고장은 진짜로 컨테이너를 멈춘다.

관제관제 화면 (NOC) :8020 — 층별 아이소메트릭 뷰 · 전력/존/근무자/경보/로그 · 강사 고장 주입 패널 운영에이전트 운영 콘솔 :8050 — 회사·부서·근무자 편성. agents/ 파일을 직접 고친다(웹 = 셸 = git diff) 실습모델 운영 (3F) :8060 — 살아 있는 서비스의 모델 manifest 를 고쳐 유지. 실패는 지표와 티켓 두 얼굴로 온다 실습인프라 요구사항 :8070 — "3층에 한 대 더" 같은 사업 언어의 요구를 받아 증설. 판정은 랩의 실제 상태로 API환경 시뮬레이터 (envsim) :8010/docs — 1F 시설 계통(전력·냉방·소방·물리보안) 물리 모델 + 시설 고장 25종. UI 는 관제 화면 API고장 주입기 (injector) :8030/docs — IT 계통 고장 47종(시스템·스토리지·네트워크·보안·부하). UI 는 관제 화면의 강사 패널

⚠️ 위 여섯은 WAF 뒤가 아니라 호스트 포트에 직접 publish 된다(.env 의 INT_HOST_IP). 운영·강사 도구라서 취약 사이트와 같은 입구에 두지 않았다.

포트로 안 열리면 이름으로 들어온다. 위 링크가 안 열리는 서버가 있다 — INT_HOST_IP 가 그 서버에서 닿을 수 없는 주소로 잡힌 경우다(예전 기본값이 호스트 전용 더미 NIC 이었다). 그때는 취약 사이트와 똑같은 입구(:80) 로 들어오면 된다. 학생 PC hosts 파일에 아래 한 줄을 더 넣는다: 
<VM_IP>  noc.kt66.lab injector.kt66.lab envsim.kt66.lab agentops.kt66.lab modelops.kt66.lab infraops.kt66.lab
그러면 포트 없이 http://noc.kt66.lab/ · injector · envsim · agentops · modelops · infraops 로 열린다. 이 경로는 web 의 Apache 를 거치지만 ModSecurity 는 끄고 지나간다 — 관리 도구는 WAF 실습 대상이 아니다.

위 도메인 모두 web 컨테이너의 Apache + ModSecurity 를 통과하여 백엔드로 reverse proxy. 직접 IP:port 접근도 그대로 살아있음 (관리/디버그용).

보안장비 교육 콘솔 (secuops-easy 특강)

방화벽·IPS·WAF 를 장비형 웹 콘솔로 직접 다루는 입문 특강. 폼 조작이 만드는 실제 명령(nft / Suricata rule / SecRule)을 미리보기로 보여준 뒤 적용한다. (각 콘솔은 fw/ips/web 컨테이너의 :8080 에서 동작 — 아래 vhost 또는 호스트 포트로 접속)

교육방화벽 콘솔 (nftables)fw-gui.kt66.lab (직접 :8081) — 룰 / NAT / conntrack / 로그 / SIEM + 침해대응 시나리오 10 교육IPS 콘솔 (Suricata)ips-gui.kt66.lab (직접 :8082) — 탐지룰 구조·작성 / eve.json / SIEM + 침해대응 시나리오 30 교육WAF 콘솔 (ModSecurity)waf-gui.kt66.lab (직접 :8083) — SecRule 작성 / CRS / audit 분석 / SIEM + 침해대응 시나리오 30

교안·실습(6주)은 CCC kt66 Training 메뉴의 secuops-easy 과목. 콘솔의 모든 동작은 적용 전 미리보기/문법검사를 거쳐 안전하게 연습할 수 있다.

학습 포인트: Wazuh agent 는 자체 binary 가 로그 수집 + 디코딩 + 알림 관리자에게 보낸다 (TCP/1514, 암호화). syslog forward 는 rsyslog 가 모든 로그를 그대로 UDP/514 로 전달하고, manager 가 직접 디코딩한다. agent = 정밀 + 보안적으로 우수, syslog = 단순 + 표준 호환. 강사의 주입도 사건으로 같은 SIEM 에 남는다 — 학생 타임라인에서 원인과 결과가 한 줄에 놓인다.

네트워크 구성 (ext → pipe → dmz → int, + app(3F GPU) / ot(1F 시설))

외부 요청은 fw(80/443) 한 곳으로만 들어와 fw(방화벽) → ips(Suricata) → web(WAF) → int 백엔드 체인을 강제로 거친다. int 의 취약 사이트는 직접 노출되지 않는다. 데이터센터를 얹으면서 두 망이 더 생겼다 — app(3F GPU 존, 터널 너머 DGX Spark 가 이 존의 구성원이 된다)과 ot(1F 시설망). 시설망을 IT 망과 분리한 것은 실제 DC 구조이자 그 자체로 교보재다. 둘 다 게이트웨이가 ips 라서, 존을 넘는 트래픽은 반드시 IPS 를 지난다.
