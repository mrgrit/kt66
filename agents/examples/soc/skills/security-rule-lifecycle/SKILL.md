# 탐지·방어 규칙 관리 — 교육용 기본 예시

## 적용 상태와 직무
이 파일은 기본 배포에 포함된 확장 실습 예시이며 현재 SOC에 자동 배정되지 않는다.
현행 SOC에는 인터넷 위협정보 수집과 SIEM·IPS·WAF 규칙 등록 도구가 없다. 제공받은
자료로 적용성을 검토하고 변경안·시험 계획을 작성할 수 있지만 수집·시험·등록 완료를
주장하지 않는다. 사용자 업무는 request_finish, 정기 업무는 허용된 증거 기록 도구를 따른다.

SOC는 분석과 탐지 후보 작성, 네트워크 담당은 허용된 방화벽/WAF 변경, 별도 권한을
부여받은 담당자/실행기는 SIEM 탐지 규칙 등록을 맡는다. SIEM 등록 담당이 구성되지
않았다면 ‘등록 담당/도구 미구성’으로 남긴다. 문서로 직무 상한을 확대하지 않는다.
기존 네트워크 WAF 변경 기능은 지정된 리터럴 페이로드용이며 모든 규칙 문법을 지원하지 않는다.

## 입력에 따른 시작점
- **매일의 신규 위협 검토:** 이전 확인 시점 이후의 취약점·공격기법·공급자 권고 중
  우리 제품·버전·노출 경로에 관련된 항목을 검토한다. 공개일, 수정일, 실제 악용 근거와
  정보 출처를 구분한다. 외부 조회 도구가 없으면 제공받은 자료의 기준 시각을 밝힌다.
- **월간/사건 분석에서 온 후보:** 원본 사건 근거, 반복 행위, 기존 탐지의 공백, 정상
  예외를 확인한다. IP 목록만으로 범용 공격 패턴을 만들지 않는다.
- 동일 취약점·패턴·규칙 버전을 다시 받으면 새 근거 또는 변경 필요성부터 확인한다.

## 작성부터 검증까지
1. 자산·제품·버전·서비스 노출과 적용성을 대조한다. 단순히 최신 이슈라는 이유로 규칙을
   추가하지 않는다. 패치·설정 변경이 필요한 항목과 보완 탐지가 가능한 항목을 구분한다.
2. 목적을 정한다: SIEM의 관측/경보인지, IPS/WAF/방화벽의 방어 조치인지 구분한다.
   대상 엔진·버전·필드/로그 소스가 없으면 실행 가능한 문법을 임의로 확정하지 않는다.
3. 변경안에는 이름·버전·근거·대상 자산/서비스·탐지 조건·심각도·중복 억제·정상 예외·
   필요한 로그 필드·성능 영향·변경 전 상태·복구 방법을 넣는다.
4. 양성 사례와 정상 음성 사례로 탐지/오탐을 검증한다. 경계값·누락 필드·우회 표현 등
   근거 있는 변형을 포함한다. 시험 도구가 없으면 사례와 예상 결과를 제시하고 ‘미검증’으로 표시한다.
5. 실제 검증 기록이 있으면 탐지 결과·오탐·필드 누락·성능 영향을 보고한다. 모델이 쓴
   기대 결과와 실행 영수증을 구분한다. 공격/정상 샘플을 운영 시스템에 임의 재전송하지 않는다.
6. 변경 범위·검증 결과·복구 방법을 검토자에게 제시하고 해당 시스템의 승인 절차를 따른다.
   작성한 에이전트가 자기 변경안을 승인하거나 등록하지 않는다.
7. 실제 등록은 담당 직무와 등록 도구, 유효한 승인, 대상/버전 일치를 확인한 실행기가 수행한다.
   초안·요청 기록·승인·등록 접수·활성화 확인을 각각 구분한다.
8. 적용 후 규칙 활성화와 의도한 탐지/방어 동작을 다시 확인한다. 과도한 오탐, 서비스 영향,
   오류가 있으면 승인된 복구 절차로 담당자가 조치하고 재검증한다. 관측 기간이 짧으면 안정화 미확인이다.

## 결과와 상태
항목별 상태는 적용 대상 아님 / 추가 자료 필요 / 초안 / 시험 대기 / 검토·승인 대기 /
등록 대기 / 적용 검증 중 / 검증 완료 / 복구 필요로 기록한다. 현재 도구로 도달한 단계만 쓴다.
대화에서는 변경안을 보고할 수 있지만 다른 담당자를 자동 실행하거나 운영에 적용했다고 말하지 않는다.

보고에는 위협정보 기준 시각, 검토 목록과 선정/제외 이유, 규칙 변경안, 실제 검증/미검증,
담당자·요청/승인/적용 상태, 다음 확인 조건을 포함한다. 변경이 필요 없으면 근거와 함께
간단히 끝낸다. 일일 작업이라는 이유로 매일 새 규칙을 강제로 만들지 않는다.

## 학생이 바꿔 볼 항목
- 어떤 자산·노출 조건의 취약점을 먼저 검토할지.
- 규칙 작성 전에 요구하는 정상 예외와 시험 자료.
- 탐지 전용으로 관찰한 뒤 차단으로 전환할 조건.
- 규칙 적용 뒤 검토할 오탐·성능·서비스 영향과 복구 조건.

직무 권한·승인 조건 변경은 업무 문서 수정과 다른 실습이다. 준비되지 않은 등록 도구는
‘항상 허용’을 선택해도 생기지 않는다. 변경안의 품질과 실제 적용 성공을 각각 평가한다.
