# 월간 SOC 종합 분석 — 교육용 기본 예시

## 적용 상태
이 파일은 학생이 수정할 수 있도록 제공한 확장 예시다. examples 경로에 있는 동안에는
실행기에 배정되지 않는다. 현재 연결된 도구만 사용하며, 없는 집계·평판·지역 조회·규칙
등록 기능을 사용할 수 있다고 주장하지 않는다. 실습 자료를 받으면 제시 자료 안에서
분석하고 실제 운영 로그 분석과 구분한다.

## 목표와 범위
지난 달에 위험이 집중된 IP, 이벤트 종류, 시간대, 서비스를 파악하고 어떤 관계가 그
판단을 뒷받침하는지 설명한다. 보고에서 탐지 규칙 개선 후보까지 연결한다.

- 예약 작업은 due_at을 기준으로 실행 시간대의 지난 달 1일 00:00부터 이번 달 1일
  00:00 직전까지 분석한다. 지연 실행되어도 원래 예약 기준 월을 바꾸지 않는다.
- 사용자 요청은 지정한 기간·시간대를 따른다. ‘이번 달’이면 아직 끝나지 않은 월임을 표시한다.
- 이전 월과 비교할 자료가 있으면 동일 기준으로 비교한다. 비교 자료가 없으면 변화율을 만들지 않는다.
- IP만으로 사람·장비·공격자를 확정하지 않는다. NAT·프록시·공유 주소와 IP 재할당을 고려한다.

## 필요한 입력
실제 조회 가능한 자료와 제시받은 자료를 구분해 목록을 만든다.

1. 기간별 이벤트 집계와 원본 증거 연결: 시각, IP/통신 방향, 내부 자산, 서비스, 이벤트 종류,
   처리 결과, 중복 기준, 관측 기간과 누락 구간.
2. IP 위험 평가·평판·블랙리스트: 점수의 정의/정책 버전, 출처, 관측일, 만료일과 적용 범위.
3. 서비스 정책: 국내 전용 여부, 허용된 외부 연계, 업무 시간·시간대, 중요도, 승인된 작업 일정.
4. 확인된 지역 정보: IP 지역 추정의 출처·기준일·불확실성. 사설 IP 또는 위치 미확인을 해외로 분류하지 않는다.
5. 기존 사건과 탐지 규칙: 실제 판정 근거, 대응/검증 상태, 규칙 적용 범위와 변경 이력.

필요한 입력이 없으면 어떤 판단이 제한되는지 적고 가능한 자료의 분석을 계속한다.
한 달 전체 로그가 없거나 페이지가 남았으면 전체 기간의 정확한 순위·건수로 보고하지 않는다.

## 기본 업무 흐름
1. 조회 범위·자료 품질·이전 보고와 중복 여부를 먼저 확인한다. 긴 로그를 모델이 반복해서
   세는 대신 제공된 집계 기능과 계산 결과를 사용한다. 계산 근거가 없으면 정식 점수는 미산정이다.
2. 다음 네 관점을 각각 검토하고 사건·원본 근거를 연결한다.
   - **위험 IP와 이벤트:** 검증된 고위험 IP가 반복적으로 일으킨 이벤트와 연관 내부 자산.
   - **위험 시간대와 이벤트:** 위험 사건이 집중된 요일·시간대 및 그 시간에 반복되는 이벤트.
   - **서비스 정책과 지역:** 국내 전용 서비스의 해외 출발지 관련 이벤트, 정상 외부 연계와 정책 불일치.
   - **블랙리스트와 공격 패턴:** 유효한 목록에 포함된 IP의 공통 공격 유형·대상·요청 특성과 기존 탐지의 공백.
3. 트래픽이 많은 시간/이벤트라는 이유만으로 위험하다고 판단하지 않는다. 가능한 경우 전체
   관측량 대비 위험 이벤트 비율과 실제 영향도 함께 확인한다. 관측량이 없는 비율은 미산정이다.
4. 같은 자료로 ‘위험 시간대’를 선정한 뒤 그 시간에 발생했다는 이유만으로 모든 이벤트를
   위험하다고 순환 판정하지 않는다. 독립된 사건 근거·서비스 맥락·과거 비교로 재검토한다.
5. 공격 시도, 차단, 서버 도달, 실행 성공, 피해를 구분한다. 위험 IP와 연관됐다는 사실과
   해당 이벤트 자체가 악성이라는 결론을 구분한다. 지역 추정과 해외 접속만으로 침해를 확정하지 않는다.
6. 높은 우선순위 후보를 원본 증거로 정밀 확인한다. 정상 업무 가설과 필요한 반증도 검토한다.
7. 확인된 반복 패턴을 탐지 개선 후보로 정리한다. 기존 규칙과 중복 여부, 탐지할 조건,
   필요한 필드, 정상 예외, 시험할 양성/음성 사례, 예상 부하, 대응 담당자를 적는다.
8. 실제 규칙 작성/변경 요청으로 배정됐고 security-rule-lifecycle 스킬이 제공되면 그
   절차로 이어간다. 그렇지 않으면 다음 작업의 입력으로 후보를 남긴다. 규칙 등록 완료로 보고하지 않는다.

## 보고 기본 형식
보고 기준 월·시간대·자료 출처·지침/평가 정책 버전을 먼저 적는다.

| 구분 | 필수 보고 내용 |
|---|---|
| 분석 범위 | 요청 기간, 실제 관측 기간, 누락/미산정, 이전 월 비교 가능 여부 |
| 위험 이벤트 | 이벤트 종류, 관련 IP/자산/서비스, 선정 이유, 실제 근거, 정상 가능성 |
| 위험 시간대 | 시간대·요일, 관측량과 위험 이벤트, 관련 업무 일정, 판단 한계 |
| 서비스·지역 | 국내 전용 정책, 확인된 해외 관측, 예외 업무, 위치 정보의 신뢰 범위 |
| 공격 패턴 | 블랙리스트 근거/유효기간, 공통 행위, 영향, 기존 탐지 여부 |
| 규칙 개선 후보 | 탐지 조건 초안, 정상 예외, 검증 자료, 담당자와 후속 단계 |
| 미해결 사항 | 필요한 증거, 요청 상태, 다음 확인 조건 |

정기 루프에서는 허용된 ticket_create로 로컬 보고서 증거를 남긴다. 사용자 조회 업무에서는
request_finish.summary에 작성한다. 파일 쓰기·티켓 도구가 없으면 사용 가능한 보고 경로를 따른다.
보고서 보존과 외부 발송, 후보 작성과 SIEM 등록을 구분한다.

## 학생이 바꿔 볼 항목
- 국내 전용 서비스에서 어떤 정상 외부 연계를 예외로 인정할지, 어떤 증거가 필요한지.
- 야간 근무·배치 작업이 있는 조직에서 위험 시간대를 해석하는 방법.
- 고위험 IP 연관 이벤트와 실제 악성 이벤트를 구분하는 추가 조사 조건.
- 어떤 패턴을 규칙 후보로 넘길지와 검증용 정상/공격 사례의 요건.

기준을 바꾸면 같은 자료에서 선정 대상·근거·미확인 사항·후속 작업이 어떻게 달라졌는지 비교한다.
결과가 더 단정적이라는 이유만으로 개선이라고 평가하지 않는다.
