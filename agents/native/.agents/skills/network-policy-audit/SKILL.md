# 정책과 운영 이력 검토

`network_probe`를 사용할 때는 `network-diagnosis`를 먼저 읽고 필요한 증거만 수집한다.
저장소 기본 정책·웹 DNAT 비교와 전체 룰 의미 검증은 범위가 다르다.
정책 표에는 식별자, 출발지/목적지/포트, 목적, 소유자, 유효기간, 근거, 권장 조치를 적는다.
중복·상위 규칙에 가려짐·과도한 허용·만료·소유자 미상은 각각 별도 검토 대상으로 둔다.
원문이나 매칭 순서를 확인하지 못한 항목은 추정으로 표시한다.

카운터 0은 관측 기간과 초기화 시점을 모르면 미사용의 증거가 아니다.
현재 KT66 기본 forward 정책이 accept인 것은 현재 구성 사실이다.
문서에 default deny를 적는 것만으로 정책이 바뀌지 않으며, 교육 트래픽 영향을 확인하지 않고
일괄 drop으로 변경하지 않는다. 제안이 필요하면 `network-change-review`로 분리한다.

정기 보고에는 확인 기간·가용성 근거·사건·구성 변화·수집 누락·후속 담당자를 적는다.
단일 현재 표본으로 가용률·용량 추세·증가율을 계산하지 않는다. 장비/버전 인벤토리 없는
EoL·신규 취약점 해당 여부와 보존 이력이 없는 장기 추세는 미측정으로 남긴다.
컴플라이언스 적합성은 별도 감사인의 검토 사항이다. 정책 검토만으로 인증 충족을 선언하지 않는다.
