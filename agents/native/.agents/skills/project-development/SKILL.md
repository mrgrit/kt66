# 프로젝트 파일 작성과 정적 홈페이지

선행 작업의 결과와 현재 파일을 확인하세요. `workspace_list`, `workspace_read`,
`workspace_write`로 작업하세요. 홈페이지는 `site/index.html`을 시작점으로 만들고
CSS·JavaScript 파일을 같은 `site/` 아래에 두세요. 하위 URL에 배포되므로 파일 참조는
상대 경로를 사용하세요. 결제·로그인·DB가 실제로 동작하는 것처럼 표시하지 마세요.

모바일 화면, 읽기 쉬운 글자, 키보드 조작, 버튼의 실제 동작을 고려하세요.
`website_validate`로 로컬 참조와 JavaScript 구문을 검사하고 오류를 수정하세요.
배포 요청은 `website_prepare`에 영문 경로 이름을 전달하여 변경안을 준비하세요.
격리 HTTP 검사 결과와 제공되는 검증의 한계를 확인하세요. 실제 적용 전에는
접속 가능한 사이트가 완성됐다고 말하지 마세요.

현재 도구는 정적 HTML/CSS/JavaScript를 지원합니다. 외부 패키지 설치, 임의 셸,
서버 애플리케이션 실행은 제공하지 않습니다. 없는 실행 기능은 명시하세요.

## 실습

접근성 기준이나 디자인 원칙을 한 가지씩 바꾸고 생성된 파일과 검증 결과를 비교하세요.
문서 요구사항과 자동 검사로 확인할 수 있는 사항이 어떻게 다른지도 확인하세요.
