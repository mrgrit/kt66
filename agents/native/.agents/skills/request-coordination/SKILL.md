# 요청 조정과 최종 검토

`request_context`로 목표, 현재 도구, 기존 담당자, 대화와 남은 예산을 확인하세요.
간단한 조회는 관련 스킬과 도구로 직접 처리하세요. 여러 산출물이 필요한 업무는
`request_plan`에 명확한 작업 지시와 선행 작업 ID를 등록하세요.

기존 담당자가 수행할 수 있으면 재사용하세요. 부족한 전문 역할만
`request_agent_create`로 구성하고, 등록된 템플릿과 실제 제공 기능을 지정하세요.
새 역할을 생성하는 이유는 업무 지시에 포함하세요. 역할을 추가해도 없는 도구는 생기지 않습니다.

최종 검토 세션까지 예산에 포함하세요. 계획을 저장했으면 계획 단계를 완료하고
끝내세요. 러너가 담당자를 실행한 후 검토 작업을 배정합니다. 검토에서는 산출물과
검증 자료를 확인하고 실패·범위 제한·적용 대기 변경안을 명시하세요.

현재 홈페이지 도구는 정적 사이트만 지원합니다. 결제·DB·서버 프로그램이 필요한
요청은 필요한 실행 환경을 설명하거나 정적 시안 등 진행 가능한 범위를 질문하세요.

## 실습

작업 분해 기준을 ‘독립 산출물별 담당’에서 ‘작성 후 별도 담당자의 검토’로 바꾸고,
생성된 계획의 선후 관계와 세션 사용량을 비교해 보세요.

## 조회 전용 요청

`scope`가 `read`이면 보고서 본문을 최종 답변에 담으세요. 파일 산출물을 추가로 약속하거나
`workspace`·`website`·`waf` 기능을 계획에 배정하지 마세요. 사용자가 요청하지 않은 파일
작성을 완료 조건으로 추가하여 조회·분석 자체를 막지 마세요.
