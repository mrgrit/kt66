# 시스템 상태 직접 점검

현재 상태를 물으면 먼저 해당 조회 도구를 실행하세요. 이전 대화에 측정 자료가
없다는 이유로 사용자에게 명령을 대신 실행해 달라고 요청하지 마세요.

- 디스크 용량: `disk_usage(target="all", threshold_pct=80)`로 호스트와 등록된
  시스템을 조회하세요. 특정 대상이나 기준을 요청하면 그 값으로 조회하세요.
- 서비스 생사·CPU·메모리: `infrastructure_read`로 실제 컨테이너 상태를 조회하세요.
  Docker의 BlockIO는 누적 입출력량이며 디스크 용량이나 사용률이 아닙니다.

디스크 답변은 기준 이상인 대상의 유무를 먼저 말하고, 시스템·마운트 지점·사용률·
가용 용량·측정 시각을 표시하세요. `incomplete_targets`는 별도로 밝히세요.
`status=partial`이면 측정한 범위에서만 결론을 내리고, `unavailable`이면 조회 실패로
보고하세요. 미측정 시스템을 정상으로 간주하지 마세요.

컨테이너는 호스트의 저장 공간을 공유할 수 있습니다. overlay와 바인드 마운트를
각각 독립 물리 디스크로 세거나 용량을 합산하지 마세요. `df`의 Use%에는 예약 블록과
정수 올림이 반영됩니다. 메모리 파일시스템과 읽기 전용 이미지는 집계에서 제외됩니다.
현재 측정만으로 증가율·장기 안정성·과거 시점의 사용률을 주장하지 마세요.

도구의 `snapshot`은 자동 보존되는 실행 증거입니다. 요청 작업 공간의 산출물이
아니므로 `request_finish.artifacts`에 넣지 마세요. 별도 파일을 작성하지 않았다면
`artifacts`는 빈 목록으로 마치고, 조회 근거는 답변과 실행 기록에서 연결하세요.

도구가 `approval_required`를 반환하면 추가 호출을 멈추고 `request_finish`에
`status=waiting_input`, 필요한 승인 내용을 `question`에 기록하세요. 사용자가
대화에서 이번만 허용·항상 허용·요청 보류를 선택합니다. 허용 후에는 현재 도구
목록과 승인 기록을 다시 확인하고 실제 점검을 이어가세요.

## 실습

80% 기준을 70%로 바꾸거나 답변에 가용 GiB 열을 추가하고 결과를 비교하세요.
조회 실패와 임계치 미만을 구분하는 원칙, 서버 권한 제한은 유지하세요.
