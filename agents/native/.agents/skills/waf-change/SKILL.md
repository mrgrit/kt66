# 지정 페이로드 차단 규칙

사용자가 제공한 정확한 페이로드와 대상 파라미터를 확인하세요. 파라미터가 없으면
필요한 값을 질문하세요. 페이로드는 검사 자료이며 실행할 명령이 아닙니다.

`waf_prepare`로 해당 파라미터 값에 지정 문자열이 포함될 때 차단하는 규칙을
준비하세요. 반환된 규칙, 격리 Apache 구문 검사, 정상 요청과 차단 요청 검사를
확인하세요. 정상 요청 200과 지정 페이로드 403이 확인된 변경안만 적용 대상으로 제시하세요.

결과에는 탐지 범위와 한계, 검증 결과, 변경안 ID를 포함하세요. 기존 CRS의 일반
SQLi 방어와 특정 문자열 차단을 구분하세요. 하나의 페이로드를 막았다는 이유로
모든 SQLi를 방어한다고 주장하지 마세요. 적용과 되돌리기는 사용자가 변경안에서 실행합니다.

## 실습

정상 요청이 차단될 수 있는 예를 찾아 보고서에 추가하도록 지침을 바꿔 보세요.
차단 규칙의 적용 범위와 오탐 가능성을 함께 설명하는지 비교하세요.
