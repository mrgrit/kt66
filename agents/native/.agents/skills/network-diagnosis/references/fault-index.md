# KT66 장애 유형 라우팅

이 표는 실패한 검사나 구체적인 증상이 있을 때만 읽는다. 명령 목록을 순서 없이 전부 실행하지 않는다.

| 관측 | 우선 분리할 것 | 확정에 필요한 증거 / 한계 |
|---|---|---|
| 컨테이너 정지 | 해당 서비스 vs 상위 경로 | Docker 실제 상태. 정지 원인은 별도 로그 필요 |
| 링크 DOWN / 라우트 누락 | 링크·주소 → 게이트웨이 → 반환 경로 | 인터페이스 상태, `ip route`, 양방향 관측 |
| FW DNAT 불일치 | 목적지 IP·포트·상위 규칙 | 저장소 의도와 실행 룰 비교. 카운터는 별도 시각의 증가분 |
| TCP 연결 실패 | FW→IPS→WAF 경계별 SYN/SYN-ACK | 한쪽 HTTP 실패만으로 IPS 차단이라고 확정하지 않음 |
| HTTP 403/5xx | WAF 차단·앱 장애·경로 장애 | 원문 탐지/접근 로그가 필요. SOC 또는 앱 담당자에게 근거를 붙인 요청안 |
| DNS 실패, 직접 IP는 성공 | 이름 해석·resolver·53번 필터 | 현재 제공 도구가 해당 질의를 지원하지 않으면 미확인 |
| 대형 패킷만 실패 | 경로 MTU / 단편화 | 동일 경로·시각·크기별 결과 필요. 단일 ping으로 판단 금지 |
| 지연/손실 | 구간별 손실·큐·카운터 증가 | 현재 probe는 정밀 성능 측정기가 아님. 별도 수집 필요 |
| 현재 검사 모두 통과 | 신고 시각·대상 차이·간헐성 | ‘현재 검사 범위 이상 없음’. 티켓의 강한 확신을 증거로 사용하지 않음 |

KT66에는 Cisco/Junos/FortiGate/PAN-OS, 광 DOM, BGP/OSPF, 무선 컨트롤러가 없다.
해당 벤더 명령·광 감도 수치·Batfish 검증을 실행했다고 말하지 않는다.
확장할 때는 읽기 전용 어댑터와 실제 버전별 검사기를 먼저 추가한다.
