# IP별 위험 평가와 정밀 조사

## 적용과 실행 범위
사용자의 방식은 IP별 다중 지표 집계 → 위험 평가 → 높은 위협 후보의 정밀 검사다.
아래 30개 지표는 사용자가 제시한 항목에 권장 항목을 더한 초기 기준 v1이다.
적용 대상은 soc-daily-risk-review 예약 또는 사용자의 명시적인 종합 위험 분석 요청이다.
오늘 경보 목록·신규 IP 수 등 단순 조회에는 siem-period-analysis, 특이 사건에는
soc-incident-investigation을 적용하며 이 스킬을 읽지 않는다. 인사·기존 결과 설명에는 신규 조사를 시작하지 않는다.

이 스킬은 역할의 `skills`에 연결된다. 정기 루틴과 사용자 업무에는 목록·설명만 전달되며
예약/요청된 종합 분석을 시작할 때 `skill_read`로 본문을 읽는다. 같은 세션에서 반복 조회하지 않는다.
실제 사용 가능 기능은 manifest와 `request_context.available_tools`를 따른다.
현재 정기 `log_read`는 최근 최대 100개 Wazuh 경보만 반환한다. 사용자 업무의
`siem_search`는 보관 경보의 기간 검색이며 한 번에 최대 7일, 페이지당 최대 200개다.
정기 루틴에는 현재 `siem_search`가 없다. 역할 스킬을 읽었다고 그 도구를 사용할 수 있는 것은 아니다.
전체 IP 집계·외부 평판·정식 점수 계산 도구는 현재 제공되지 않는다. 이런 기능이 없으면
기존 도구로 증거를 조사하고 해당 단계는 미산정·부분 분석으로 남긴다. 구현되지 않은 도구 이름을 호출하지 않는다.

## 1. 범위와 이전 회차 확인
- 정기 분석은 트리거·직전 처리 위치·미해결 사건을 확인한다. 사용자 상대 시간은 최신
  메시지의 `turn.sent_at`을 기준으로 고정한다. 시작·종료·시간대를 기록한다.
- 인바운드는 외부 출발지, 아웃바운드는 외부 목적지를 분석 주체로 한다. 내부→내부 및
  방향을 확인할 수 없는 기록은 별도로 남긴다. 로그 필드와 자산 대장으로 방향을 확인한다.
- 기본 관측 창은 최근 10분·1시간·24시간, 장기 맥락은 30일이다. 자료와 예산이 있을 때
  필요한 창만 조회한다. 30일 보관이나 정상 기준이 없으면 있는 것처럼 계산하지 않는다.
- IP별 요약과 함께 내부 자산·계정·서비스·세션·시각의 연결을 보존한다. NAT 변환 기록,
  신뢰된 프록시 설정·전달 헤더, DHCP·자산 이력 등 확인된 자료로만 주체를 연결한다.
  사설 주소·공유 주소·CDN 주소라는 이유만으로 안전하거나 동일 주체라고 단정하지 않는다.

## 2. 수집과 집계의 품질 확인
조회 원본·쿼리 기간·실제 관측 기간·도구 영수증·스냅샷/해시를 기록한다. 페이지가 남거나
자료가 잘렸으면 부분 조회다. 최근 tail 결과는 완전한 증분 수집 또는 전체 모집단이 아니다.
이벤트 ID가 있으면 활용하고, 없으면 시각·센서·자산·규칙·세션/요청 정보를 조합한 중복 기준을 기록한다.
센서별 관측 수와 동일 행위 수를 구분한다. 다른 센서에서 같은 행위를 잡은 것은 교차 근거이며
독립 공격 여러 건으로 무조건 가산하지 않는다. 원본 행 수는 중복 제거 전 값으로 따로 보존한다.

지표마다 값·단위·창·방향·분모·출처·계산 방법·수집 상태를 남긴다.
상태는 `measured`(계산 근거 있음), `partial`(일부 자료), `unavailable`(자료/기능 없음),
`not_applicable`(대상에 적용 안 됨)을 구분한다. 0은 실제 관측 범위에서 0일 때만 사용한다.
로그 수집 중단·시간 오차·보관 부족은 별도 조사 사항이다. ‘탐지 없음’을 ‘위협 없음’으로 바꾸지 않는다.

## 3. 지표 30개 정의
원자료가 충분하고 허용된 집계 기능이 있을 때 계산한다. 긴 원문을 반복해서 읽고 모델이
수작업으로 전체 통계나 점수를 추정하지 않는다. 제한된 표본에서 확인한 값은 표본값이라고 명시한다.

| ID | 지표 | 정의와 해석 조건 |
|---|---|---|
| F01 | 로그 행 수 | 해당 IP·기간의 원본 행 수. 재전송·센서별 중복 포함 여부 명시 |
| F02 | 고유 이벤트 수 | 선언한 중복 기준으로 제거한 이벤트 수 |
| F03 | 세션 수 | 실제 세션 식별자로 집계. 식별자가 없으면 추정 세션 수와 구분 |
| F04 | 분당 최대 요청 수 | 요청 로그의 1분 버킷 최댓값. 경보 수를 요청 수로 대체 금지 |
| F05 | 요청량 증가율 | 동일 서비스·요일·시간대 기준 대비 증가. 기준 0/부재면 비율 미산정 |
| F06 | 접근일 수 | 지정 기간·시간대에서 활동한 고유 날짜 수. 지속성 지표이며 많다고 악성 아님 |
| F07 | 활동 시간대 수 | 활동한 1시간 버킷 수. 24시간 서비스·예약 작업 맥락 고려 |
| F08 | 업무외 접근 비율 | 대상 자산의 업무 달력 밖 요청/전체 요청. 달력 없으면 미산정 |
| F09 | 최초 관측 후 시간 | 보관 자료의 최초 관측부터 기준 시각까지. 인터넷 전체 최초 출현 아님 |
| F10 | 통신 주기성 | 같은 자산·서비스의 세션 간격 분포. 표본 수·간격 변동 함께 제시 |
| F11 | 연관 내부 자산 수 | IP와 통신/공격 관계가 관측된 고유 내부 자산 수 |
| F12 | 목적지 포트 수 | 고유 목적지 포트 수. 동적 포트·중계 특성 고려 |
| F13 | 서비스 수 | 식별 가능한 프로토콜·애플리케이션 종류 수 |
| F14 | URL 경로 수 | 일관되게 정규화한 경로 수. 민감한 쿼리 값은 제거하고 기준 명시 |
| F15 | 시도 계정 수 | 인증 로그의 고유 대상 계정 수. 계정 정보 없으면 미산정 |
| F16 | 이벤트 종류 수 | 정규화한 탐지 종류와 목록. 센서별 규칙 ID 개수와 구분 |
| F17 | 고위험 탐지 수 | 출처별 심각도를 정규화한 뒤 중복 제거한 탐지 수 |
| F18 | 인증 실패율 | 실패/전체 인증 시도. 경보에 실패만 있으면 전체 실패율 산정 금지 |
| F19 | 공격 문자열 탐지 수 | 근거가 있는 공격 요청 수와 유형. 문자열 존재는 성공 증거 아님 |
| F20 | 차단 후 재시도 수 | 동일 대상·행위의 시간순 차단 이후 재시도. 반복 규칙 경보와 구분 |
| F21 | 외부 송신량 | 내부 자산→외부 IP 방향 바이트 합. 흐름 방향과 단위 확인 |
| F22 | 송신/수신 비율 | 동일 연결 범위의 바이트 비율. 분모 0이면 별도 표시 |
| F23 | 신규 목적지 여부 | 선언한 과거 관측 창에 없던 목적지. 보관 부족이면 신규 여부 불명 |
| F24 | 조직 내 접속 희소성 | 관측 가능한 내부 자산 중 해당 IP 접속 자산 비율. 전체 자산 수와 구분 |
| F25 | 비표준 포트 비율 | 서비스 정책상 비표준인 연결/해당 서비스 전체 연결. 기준 없는 포트 추정 금지 |
| F26 | IP 평판점수 | 제공자의 원점수·척도·의미·조회 시각 보존. 서로 다른 점수 직접 합산 금지 |
| F27 | 독립 위협정보 출처 수 | 동일 원천의 재배포를 중복 제거한 악성 근거 출처 수 |
| F28 | 악성 관측 최신성 | 조회 시각과 별개인 실제 악성 관측 시각의 경과. 정보 부재는 정상 아님 |
| F29 | 연관 자산 중요도 | 승인된 자산 대장의 중요도. 주소·호스트 이름만으로 추정 금지 |
| F30 | 승인 업무 일치 여부 | 유효한 작업 승인·일정·프로세스·목적지와 관측의 일치. 한 항목 일치로 전체 면제 금지 |

## 4. 위험 평가와 조사 대상 선정
집계·점수는 재현 가능한 계산 결과를 사용한다. 평가 정책이 제공되면 버전·지표 변환·
방향별 가중치·그룹 상한·시계열 감쇠·결측 처리와 항목별 기여도를 함께 보존한다.
관련성이 큰 지표와 같은 공격의 중복 탐지를 독립 근거처럼 무제한 합산하지 않는다.
인바운드와 아웃바운드에 동일한 가중치를 강제로 적용하지 않는다.

정식 계산기/정책이 없으면 `risk_score: null`, 이유는 ‘평가 기능 또는 정책 미제공’으로 남긴다.
임의의 0~100점이나 침해 확률을 쓰지 않는다. 향후 점수가 제공되더라도 우선순위 점수와
보정된 침해 확률은 다르다. 증거 신뢰도와 데이터 완전성을 위험 점수와 별도로 보고한다.
전수 수집을 확인할 수 없으면 완전성 백분율 대신 확인 범위와 누락을 쓴다.

조사 우선순위는 강한 침해 증거와 중요 자산 영향 → 새로 결합된 여러 증거 → 기존 사건의
새 자산·새 행위 → 단독 약한 징후 순으로 판단하고 이유를 적는다. 정식 점수 도입 시
70점 이상 또는 1시간 25점 상승은 초기 검증용 후보 기준이며 현재 자동 트리거가 아니다.
강한 단일 증거는 점수 부재/낮은 점수에도 조사한다. 계획된 표본 검토로 낮은 점수의 누락도 확인한다.
백업·업데이트·공유 서비스도 침해될 수 있다. 정상 맥락 하나로 강한 악성 증거를 지우지 않는다.

## 5. 정밀 조사
1. 선정 이유를 지표·이벤트·변화 시점으로 특정한다. 공격 가능성과 정상 업무 가능성을 함께 정리한다.
2. 조회 범위 안에서 전후 이벤트를 시간순으로 연결한다. 탐색→인증→실행→외부 통신 등
   실제 확인된 연결과 추정 관계를 구분한다. 같은 IP라는 이유만으로 서로 다른 사건을 합치지 않는다.
3. 관련 원문·요청/응답·탐지 규칙·통신 흐름을 조회 가능한 범위에서 대조한다. 탐지된 공격 시도,
   방어 장비의 처리, 서버 도달, 실행 성공, 피해를 각각 구분한다. 필요한 센서가 없으면 결측이다.
4. 정상 가설은 승인된 변경·예약 작업·정상 프로세스·자산 소유자의 확인 등으로 검증한다.
   예: 파일 변경이 업데이트 패턴과 비슷하면 실제 패키지 변경 기록을 요청한다. 패턴만으로 종결하지 않는다.
5. SOC 권한 밖 자료는 담당자에게 보낼 요청안을 작성한다. 대상·기간·필요 증거·현재 가설·
   우선순위·응답 후 판정 기준을 명시한다. 실제 전달 도구와 접수 증거가 없으면 ‘전달 필요’다.
6. 예산 안에서 결론을 낼 수 없으면 확보한 증거와 다음 조회 위치를 남긴다. 무한 재조회나
   결론을 얻기 위한 표본 범위 변경은 하지 않는다.

## 6. 판정·사건 상태·재작업
판정은 `악성 확인`, `악성 의심`, `정상 근거 확인`, `판단 보류`로 남기고 근거와 반증을 적는다.
‘악성 확인’에도 공격 시도 확인인지 침해 성공 확인인지 명시한다. 정상 업무 확인과 탐지 규칙의
오탐 여부는 별개로 설명한다. 증거 없는 정상 추정·평판 부재·최근 경보 없음은 종결 근거가 아니다.

사건 상태는 신규·조사 중·증거 대기·대응 요청 필요·대응 확인 대기·종결을 구분한다.
종결에는 판정 근거 또는 담당자 조치 결과와 사후 확인이 필요하다. 도구의 회차 완료가 사건 종결을 뜻하지 않는다.
재조사는 새 근거, 관련 자산 확대, 상충하는 결과, 대응 실패, 약속된 확인 시점 도래가 있을 때 한다.
같은 증거만 반복되면 기존 사건에 연결하고 추가 모델 작업·새 티켓을 만들지 않는다.

정기 루틴에서 허용되는 `cycle_state`는 다음 키만 갱신한다. 기존 기록을 통째로 덮어 지우지 않는다.
- `analysis_checkpoint`: 실제 조회 출처·기간·처리 위치·남은 범위·완전성. tail 최종 시각을 완전 처리 지점으로 쓰지 않는다.
- `ip_risk_cases`: 사건별 식별자·IP/방향/자산·상태·정책 버전·점수 산정 여부·핵심 증거·후속 담당·다음 확인 조건.
- `capability_gaps`: 미제공 자료/도구·영향·첫 확인·최근 확인·변경 여부. 동일 결핍만으로 반복 티켓을 만들지 않는다.
- `triaged_alert_ids`: 처리한 근거 식별자. 새로운 관련 증거까지 중복으로 폐기하지 않는다.
- `known_false_positives`: 정상 확인 근거·적용 범위·확인일·만료/재검토 조건이 있는 항목만 저장한다.
- `active_campaigns`: 실제 연관 근거가 있는 진행 사건. IP 일치만으로 캠페인 확정 금지.
- `last_risk_review`: 종합 분석 루프에서만 기준 시각·보고서 경로·지침 버전·분석 범위/한계·다음 작업을 저장한다.

과거 자유 형식 기록은 참고 자료다. 기존 오탐 목록에 실제 사건·보류가 섞였거나 근거가 없으면
현재의 정상 허용 목록으로 사용하지 않는다. 변경 근거를 남기고 미확인 기록은 보류로 재분류한다.
사용자 업무에 상태 쓰기 권한이 없으면 결과와 후속 작업을 `request_finish`로 남긴다.

## 7. 보고·비용·교육
보고에는 기간·시간대·분석 방향·대상, 수집 범위와 한계, IP별 지표/미산정 항목,
위험 점수/미산정 이유, 선정 이유, 원본 증거 식별자, 판정·불확실성, 요청/응답 상태,
다음 작업을 포함한다. 전체 30열을 매번 긴 표로 반복하지 않고 이번 결정을 바꾼 값과 결측을 우선 제시한다.
사용자 대화는 `request_finish`의 실제 조사 여부를 정확히 선택한다. 정기 루틴은
`activity_note`의 상황/계획 및 최종 검토에 핵심 증거와 재작업 사유를 남긴다.

기본 점검 10분과 적응형 5→2→1분 전환은 실행기 정책이다. 스킬이 자체 타이머나 반복
세션을 만들지 않는다. 현행 보안 모니터는 최근 경보의 변화 감지이며 IP 위험 평가 엔진이 아니다.
호출·시간 예산을 지키고, 자료가 바뀌지 않은 사건의 동일 조회·평판 조회·티켓 작성을 반복하지 않는다.
낮은 우선순위 대상의 표본 검토는 명시된 검토 작업이나 남은 예산에서 수행한다.

학생은 지표 해석·우선순위·조사 분기·보고 형식을 수정하고 동일 사례의 지침 버전,
도구 영수증, 판정과 한계를 비교한다. 문서 변경은 모델 지침을 바꾸며 도구 추가나 강제
단계 검증을 구현하지 않는다. 가중치 자동 계산과 단계별 완료 보장은 별도 실행 코드가 필요하다.
