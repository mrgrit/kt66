# 변경안 작성과 독립 검토

출발지·목적지·포트·목적·소유자·기간·영향 서비스가 있어야 변경안을 만든다.
ANY·광대역 허용·관리 경로 변경에는 범위 축소와 별도 검증이 필요하다.
신고 내용과 현재 설정·증거를 구분하고 읽기 전용 점검으로 기존 규칙과 충돌 여부를 확인한다.

작업계획서에는 대상/버전, 증거 참조, 의도한 차이, 영향 범위와 미측정 범위,
사전 조건, 정확한 변경 산출물, 사후 성공 기준, 복구 산출물·발동 조건, 승인자를 적는다.
숫자로 측정한 영향과 정성적 추정을 구분한다. 검증기 없는 ‘안전 점수’를 만들지 않는다.

현재 KT66에서 제공되는 실행 경로를 따른다.
- 대화는 읽기 전용이다. 변경안 구현은 업무 요청으로 이어갈 수 있도록 안내한다.
- WAF 변경안은 업무 요청의 `waf_prepare`와 기존 격리 검증·관리자 적용 경로를 사용한다.
- 범용 nftables/라우팅 쓰기 도구는 제공되지 않는다. 승인됐다는 말만으로 셸·SSH로 우회하지 않는다.
- IC/서비스데스크는 배정, 네트워크 담당은 조사·계획, 운영 리드는 독립 검토,
  서버의 변경 적용기는 승인된 산출물만 실행한다. 작성자가 스스로 승인하지 않는다.
- 자동 롤백 타이머·사전/사후 검증을 지원하지 않는 네트워크 변경은 자동 적용 불가로 남긴다.
  Junos/IOS-XE 명령을 Linux nftables에 적용하거나 Batfish/pyATS가 설치돼 있다고 가정하지 않는다.

검증 실패는 구체적인 오류로 작성자에게 돌려보낸다. 최대 3회 수정 후에도 해결되지 않으면
사람에게 넘긴다. 원본/대상/계획이 바뀌면 기존 승인·검증을 재사용하지 않는다.
결과에는 `준비 / 검증 실패 / 검토 대기 / 승인 / 적용 / 사후 확인 / 복구`를 구분한다.
