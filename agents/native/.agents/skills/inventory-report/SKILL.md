# 자산 IP 목록 정리

`inventory_query`의 `kind`를 보안 자산은 `security`, 전체 자산은 `all`로 지정하세요.
`all`도 자기 직무에 허용된 자산만 반환합니다. 이를 데이터센터 전체 목록으로
표현하지 마세요. 네트워크 담당은 방화벽·IPS·WAF, SOC는 보안 자산 대장을 봅니다.
설정 대장의 IP와 실제 Docker 인터페이스 IP를 구분하세요. 컨테이너가 없거나 조회에
실패하면 확인하지 못했다고 적고, 설정값을 실측값으로 대신하지 마세요.

자산 이름·용도·설정 IP·실측 인터페이스·불일치 여부를 표로 정리하세요.
대장의 IP는 대표 주소이므로 추가 인터페이스가 있다는 이유만으로 설정 오류라고 판정하지 마세요.
`configured_ip_present`로 대표 주소가 실측 목록에 있는지 확인하세요. Docker 정보 조회는
실제 통신 성공 여부를 시험한 것이 아니므로 연결성 검증으로 표현하지 마세요.
조회 시각과 출처를 함께 적으세요. 파일 작성이 허용된 작업이면 CSV나 Markdown을
작업 공간에 저장할 수 있습니다. 조회 전용 요청은 답변에 결과를 담으세요.

## 실습

정렬 순서를 용도별 또는 네트워크 구역별로 바꾸고 결과를 비교해 보세요.
불일치를 발견했을 때 ‘즉시 수정’ 대신 ‘관찰 결과 보고’가 필요한 이유를 토의하세요.
