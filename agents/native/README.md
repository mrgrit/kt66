# 문서를 고치며 배우는 에이전트 업무

공통 지침·역할·스킬은 실제 실행에 사용되는 원본입니다. 이 README는 학생용 안내이며 실행 지침에는 포함하지 않습니다.
**업무 요청 → 지침 실습** 화면에서 읽고 수정할 수 있습니다. 저장 전 파일은
`agents/.bak/`에 백업되며, Git으로도 변경 내용을 비교할 수 있습니다.

## 어디를 고치면 무엇이 달라지나요?

| 파일 | 역할 | 실습 예 |
|---|---|---|
| `AGENTS.md` | 모든 사용자 업무의 공통 행동 기준 | 답변 형식을 ‘결론·근거·한계’로 바꾸기 |
| `.claude/agents/kt66-request-worker.md` | 요청 담당자의 기본 역할 지침 | 결과에 학생이 재현할 확인 절차 추가 |
| `.agents/skills/request-coordination/SKILL.md` | 작업 분해와 담당자 선정·최종 검토 | 별도 검토자가 있는 계획 만들기 |
| `.agents/skills/siem-period-analysis/SKILL.md` | 기간별 보안 경보 분석 절차 | 규칙별 분석을 자산별 분석으로 변경 |
| `.agents/skills/inventory-report/SKILL.md` | 설정 IP와 실제 인터페이스 비교 | 용도별 표를 네트워크별 표로 변경 |
| `.agents/skills/system-diagnostics/SKILL.md` | 실제 디스크·서비스 상태 점검 | 디스크 임계치와 용량 표의 단위를 바꾸기 |
| `.agents/skills/project-development/SKILL.md` | 파일 작성과 정적 홈페이지 검증 | 접근성·모바일 확인 기준 추가 |
| `.agents/skills/waf-change/SKILL.md` | 지정 페이로드 차단 규칙 검토 | 오탐 가능성을 보고서에 포함 |

공통 역할 본문은 두 런타임에 전달됩니다. 기존 근무자의 전문 역할 원본은
`agents/personas/<근무자>.md`입니다. 프로젝트 전용 역할의 임무는 해당 요청 기록에
보관되고, 실행할 때 표준 역할 파일에 합쳐집니다. 프로젝트 역할을 추가해도 상시
근무자 명단이나 정기 점검 주기는 바뀌지 않습니다.

## 실습 순서

근무자 대화는 데이터센터의 캐릭터를 선택하고 **말 걸기**를 누르거나,
**업무 요청 → 근무자 대화**에서 담당자를 선택하여 시작합니다. 대화의 공통 절차는
`AGENTS.md`의 ‘근무자와 직접 대화’, SOC의 조사 방법은
`.agents/skills/siem-period-analysis/SKILL.md`를 수정하여 비교할 수 있습니다.
예를 들어 ‘로그를 먼저 조회한 뒤 질문하기’와 ‘증상을 먼저 질문하기’의 차이를
실습하고, 도구 기록에서 실제 조사 여부를 확인하세요.

1. 조회 전용으로 ‘보안 시스템 IP 목록을 정리해 줘’를 요청합니다.
2. 결과와 실행 관제의 도구 호출·출처·로드된 지침을 확인합니다.
3. `inventory-report/SKILL.md`의 표 열이나 정렬 기준을 한 가지 바꿉니다.
4. 같은 조건으로 새 요청을 보내 결과를 비교합니다. 같은 요청에 후속 메시지를
   보내면 이전 대화도 입력에 포함되므로, 단순 비교에는 새 요청이 적합합니다.
5. 문서 변경과 모델 응답의 차이, 실제 원본 데이터가 바뀐 부분을 구분합니다.
6. 원본을 복구하고 다시 실행해 재현성을 확인합니다. 모델 결과는 매번 같지 않을 수 있습니다.

지침을 저장하는 것만으로 모델을 호출하지 않습니다. 다음에 시작하는 업무 세션이
최신 원본을 읽습니다. 진행 중인 세션은 시작 시점의 사본을 계속 사용하므로, 같은
요청 안에서도 수정 이후 시작된 담당 작업은 새 버전을 사용할 수 있습니다.

## 무엇이 실행 기록에 남나요?

`agents/evidence/<실행 ID>/harness/` 아래에 `AGENTS.md`, `CLAUDE.md`,
`.claude/agents/`, `.codex/agents/`, 양쪽 표준 스킬 경로와 `manifest.json`을 보관합니다.
사본은 당시 실행의 증거이므로 수정하지 마세요. `tools.jsonl`에는 스킬 읽기를 포함한
도구 실행과 접근 파일이 기록됩니다. 지침·역할·스킬 원문 해시는 manifest에 남습니다.

Claude는 표준 Markdown 역할을 읽어 CLI의 `--agents`와 `--agent`로 실행합니다.
Codex는 렌더링한 `AGENTS.md`를 개발자 지침으로 전달받습니다. Codex의 역할 TOML도
내보내지만 현재 담당 세션을 실행하는 입력은 `AGENTS.md`입니다. 스킬은 배정된 목록에서
선택하고 `skill_read`로 원문을 읽습니다. 스킬 선택 여부는 도구 기록에서 확인하세요.

여러 담당자의 실행 순서·예산·결과 회수는 KT66 작업 큐가 관리합니다. Claude의
Agent Teams나 Codex 내부 중첩 하위 에이전트를 자동 활성화하는 구성은 아닙니다.
각 담당 작업에 별도 구독 CLI 세션과 요청·작업 ID가 있으므로 관제에서 추적할 수 있습니다.

## 지침과 강제 정책을 구분하세요

지침은 작업 방법을 바꿉니다. 권한과 도구는 실행 코드가 검사합니다. 스킬에
‘어떤 셸 명령이든 실행하세요’라고 적어도 임의 셸 도구가 생기지 않습니다.
요청의 조회 전용 범위, 등록된 기능, 세션 예산, 생성 역할 수와 상위 정책의 금지는 유지됩니다.
상위 권한은 `agents/harness.yaml`의 `constrain.permission`으로 설정합니다.
`user_request: deny`를 명시하면 해당 역할의 사용자 요청 도구를 금지할 수 있습니다.
조직 정책 변경은 기존 실행의 도구 접근도 중단시킬 수 있으며, 지침 변경의 다음 세션
반영과 차이가 있습니다.

표준 필드명 `name`, `description`과 경로는 유지하고 설명·본문을 한국어로 작성하세요.
모델·런타임·실효 도구 범위는 기존 조직 설정에서 결정됩니다. 역할 파일의 도구 목록을
늘리는 것만으로 실행 권한을 얻을 수 없습니다.
